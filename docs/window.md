# Use the window

Part of [AGENTS.md](../AGENTS.md)'s Run, use and check it; the other parts are listed there.

- **The window's shell** ([0070](archive/decisions/0070-the-windows-shell.md)): the rail at the left has Home at the top, Agents and Plugins under it (the open one lit) and, at its foot, Update while a release is ready above the Settings cog. The top line above the frame has the open chat's title and its More, then at the right the Agents button, the questions button and the chat sidebar's button, open or closed. Agents opens a panel like Questions': each agent of the chat with its fill ("96K of 500K", New before its first call), Compact (Waiting, then Compacting, until its compaction's turn ends) and the commands its engine still runs in the background with how long each has run; a blue dot on the button while any runs. The replay engine's `background` recording holds one command until its `hold` row is let go. The frame holds the sidebar, the chat and, while it is open, the chat's sidebar with its tabs: Home, always first, with Find a file at its top, then Open (the Files and Design tiles) and the board; Files once opened, the tree of the project's folder, Shared, the project's Designs and each agent's folder for this chat, under Filter files; Design once opened, the project's designs (each folder in its part of Designs that holds an HTML page), newest first, each with the agent whose step last wrote in it when the chat's steps say so, "1 page" or its count of options, and Writing while that agent's turn runs, or No designs; a design opens in its own tab, its page in the same sealed frame as an HTML file's, with A, B, C for its pages in their files' order when it has more than one, and Writing. The design's frame loads again each time an agent's step that wrote or edited a file in its folder ends, back at the page's top as a fresh load is, and the list and the options read the folders again; only a step that names a full path counts: Claude Code's Write and Edit, and Codex's file change by the first file it names; and each file opened from the tree, or from the chat (an agent's link to a file, a tile that isn't a picture, a file on a question; a path that isn't full is in that agent's folder, and in a Markdown file's own links, beside that file), with Copy: Markdown as a page and CSV or TSV as a table, each with Source for its own text (a table draws its first 2,000 rows), an HTML page as it looks, filling the tab and keeping its own colours, its scripts running in a frame sealed from Gathr and from this PC (it loads only the files in its own folder and below, and `https:` addresses), with Source for its own text (a page over 2 MB shows as it looks, without Source and Copy), code as numbered lines coloured by its ending (up to 150,000 characters), other text as plain numbered lines, or a picture. A file opened from the chat opens the sidebar when it is closed. Which tabs are open is kept per chat until the window closes. A file tab scrolled partly out of sight isn't drawn. Words in either box list the files whose name holds them in place of what is under the box (No files found when none), a moment after typing stops; a click, or Enter on the marked one (the arrows move it), opens the file and empties the box, and the tree comes back with its folders as they were.
- **No system title bar** (0070): the top line is the window's bar. Press any part of it that isn't a control to move the window, double-click it to maximize or restore. On Windows, Minimize, Maximize (Restore while maximized) and Close are at its right, Close in the window's top right corner; the edges and corners resize, Win+Arrow snaps. On the Mac the system's three buttons are at its left. Every screen has the top line, a chat or none, and it stays live while a dialog (Settings, New project, a confirm) is open: the dialog holds the same band over it. "Start failed" keeps the system's title bar. With no title bar, a test folder's window name ("Gathr (dev 47101)") shows only in Alt+Tab and the taskbar's preview. The page's commands are `capabilities/window.json`'s; one the window refuses is a `gathr.ui.window.frame` error, named for the command. A test can't drag a native window: `ui/src/TopLine.test.tsx` checks what the page draws and sends, and the rest is checked by hand in the dev window (`gathr dev --window`) or the installed app on its own `--data` folder.
- **Chats and projects in the window:** New (or a project's + in the sidebar) opens a draft, and the chat is made at its first send, in the project picked above the composer. New project, last in that picker, takes a name, a git folder and up to 5 agents with their roles. A project's More in the sidebar has Project settings, which opens Settings > Projects at it: its name, folder and team, saved with one Save. The message box has no picker (0028): a new chat's hint names who gets a message that names nobody (the assistant picked on the Agents screen, or the project's lead), typing @ lists the chat's agents with their descriptions (in a chat with no project, every agent, those not in it under Bring in; in a new one, the assistant first and nobody under Bring in), only a name picked from that list counts and is blue, in the box and in the sent message (a typed `@Ann` is plain text in both), and by Send who gets what is typed: every agent picked, "To Ann" or "To Ann and Bo" with their faces, "Bo joins" or "Bo and Cy join" for agents a chat with no project brings in ([0028](archive/decisions/0028-team-chats.md)). The replay engine plays its recording once per process and Gathr reuses an engine for an agent's next turn, so for several turns repeat the recording's rows once per turn.
- **A chat's dot in the sidebar** (0040): one dot at the end of a chat's title, grey and breathing while a turn of it runs, blue once it needs you (an approval, a question or a sign-in); blue wins, and reduced motion keeps it still. To see both without a login, start the service on the replay engine ([running.md](running.md)): a recording with a `sleep` row holds a turn open, and `approval.jsonl` asks for an approval. `gathr diag health` lists the same chats under `chats`.
- **Archive and Delete in the window:** the top line's More menu and each sidebar row's (it shows while the pointer or the keyboard is on the row) have Archive (Restore once archived) and Delete, each asked first. Archived chats are in the folded Archived group at the foot of the sidebar and open read only, with Restore.

- **Delete a project or an agent** ([0069](archive/decisions/0069-deleting-a-project-or-an-agent.md)): a project's More in the sidebar has Delete after Project settings, a project's page in Settings > Projects has Delete at its title's right, and an agent's page on the Agents screen has it in its header. Each opens the one confirm, "Delete Larder?", with what the service counts under it, read when it opens: "4 chats will be deleted. Files are kept.", "2 tasks will be cancelled.", "1 task will be cancelled. Ann becomes lead.", "1 project and 2 chats will be deleted. Files are kept." Delete waits for those words; counts that fail to load show Counts failed with its reference, and Delete stays off. The lists change at once, and an open chat deleted with them gives way to its neighbour in the sidebar, else New, never to a chat going with it. Folders the delete couldn't remove yet show as Some files weren't deleted, with their reference, and the sweep tries them again. A removed agent's old messages keep its name; it is in no list, @ list or team. No Undo. To try one, start a dev service with `--seed`, add a project and an agent on a throwaway git folder through the API, and delete them there.
- **Search in the window:** Search under New, or Ctrl K (Cmd K on macOS), searches chat titles and saved messages across chats (0035); the query stays between openings. Up and Down move one cursor over Chats then Messages, Enter opens the row's chat. `gathr.ui.search.error` records a failed search with its `ref`.
- **Pause and stop in the window:** the More menu by the chat's title in the top line has Pause, then Resume, or Restart after a stop; the composer's Stop while a turn runs is Stop now for the chat. The tray has Pause all and Resume all. The replay engine takes an interrupt only while it streams, so to try Stop now on a held round, let it stream first.
- **The window's own theme follows Theme** (Settings > General), for what the system still draws of it: the page calls the window's `set_theme`, only from `http://127.0.0.1` (`crates/gathr-app/capabilities/theme.json`); a refusal is a `gathr.ui.window.theme` error. To check System, drive the window without `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port`: with it, the page always reads the system as light.
- **Updating Gathr in the window** (0032): Gathr never updates by itself. While a release is ready, a blue Update icon shows on the rail, above the Settings cog; one click updates the service and the window: what runs is stopped and carries on by itself on the new version. Meanwhile a turning loader shows in its place, named "Updating"; the page stays and reconnects, then the window installs its own part of the release and restarts once, and the page loads again. The tray has no update item. Settings > General shows the version, the same Update, Check for updates, and the last failure: "The last check failed" on the row, or, while a release is still ready, a card with its reference. To check: `cargo nextest run -p gathr --test update_room --test app_update`, and in `ui/`, `npx vitest run src/update.test.tsx src/settings/AppVersion.test.tsx`.
- **The window updates itself** (F7): a release build checks `latest.json` at start and every hour, downloads the update and checks its signature, then installs it at once if the window is hidden in the tray, else when it's next hidden. After the person's Update it doesn't wait: when the window signs in to the new service and `<data>/app/current.json` names a release newer than its own, it installs at once, shown or not (`gathr.ui.update.install` with `via: "update"`; `"hide"` otherwise). Only the window restarts, shown or hidden as it was (a marker, `window-restart-shown` or `window-restart-hidden`, in the data folder); the service keeps running. Text typed in a message box and an open dialog don't survive that restart: the page keeps them in memory only. When the service hands over to its own update, the window signs in to the new one by itself (`gathr.ui.window.follow`); when the service stops answering for 3 s while the window is open, the window starts it again the way a launch does, so a new copy that died on trial rolls back at once (`gathr.ui.window.restart`; a failed restart goes to the crash log). A window showing Start failed tries the same every 3 s, so it takes up a folder an old service let go of without a relaunch; to check, hold `<data>/gathrd.lock` from another process while it opens, then release it. To stop a test service for good, quit or stop the window first. A debug build never checks. Events are `gathr.ui.update.check` and `gathr.ui.update.install`. To try one locally: build two versions with `release.mjs` and the Tauri CLI, adding a `--config` whose `plugins.updater` has your own test key's `pubkey`, `endpoints` `["http://127.0.0.1:47199/latest.json"]` and `dangerousInsecureTransportProtocol: true` (sign with that key in `TAURI_SIGNING_PRIVATE_KEY`, never the real one), with `GATHR_APP_FEED=http://127.0.0.1:47199` set so the service checks the same feed; serve the newer one's folder after `release.mjs feeds <version> <folder> http://127.0.0.1:47199` on that port; install the older one with `<setup>.exe /S /D=<folder>` (it also adds a desktop shortcut: delete it, and run `uninstall.exe /S` when done), and open it with `--data`. A PR's build artifact does the same with the real key.
- **Notifications** ([0058](archive/decisions/0058-gathr-tells-you-outside-the-window.md)): when a chat starts needing you, or its agents have all stopped, and the window is hidden, minimized or not focused, the installed app shows a system notification: the chat's title, then "Needs you" or "Work has stopped". Stopped is told at the second read (5 s apart) that finds no turn of the chat running or about to start by itself, whatever stopped it: the work is done, an agent is out of usage, or the chat was paused, by you or at the hand-off limit. Not while it needs you, during Pause all, or once the window has been in front since it stopped. Needs you comes once per chat until the window has been in front, if only for a moment; with it in front, none. During Pause all it holds them, except a sign-in and an approval Gathr itself asks for, and Resume all shows one, "Resumed", "3 chats need you". At a start with chats already waiting on you and the window not in front, one: the chat's, or "Waiting on you". A click brings the window forward on that chat; a click on an old one Gathr no longer keeps brings it forward with no chat. There is no setting: Windows and macOS have their own notification settings. The dev window shows none. Every outcome is a `gathr.ui.notify` event (`shown`, `held`, `skipped`, `clicked`; `gone` when a clicked chat no longer exists); read them with `gathr diag query "SELECT time, status, attrs FROM event_log WHERE name = 'gathr.ui.notify' ORDER BY ts"`. The tests: `cargo nextest run -p gathr --lib -E 'test(notice)'`, `cargo nextest run -p gathr --test chat_state --test waiting`, and in `ui/`, `npx vitest run src/open-chat.test.tsx`. What they can't do is show a notification or click one, so those are checked by hand, on the installed Gathr with its own data folder: on a test folder the app's identifier carries a key, so the notification's name and icon aren't known, and a debug build shows as Windows PowerShell. Don't run them on a PC someone is using without telling them: notifications appear on screen.
  - **The owner's check on Windows,** after an update:
    1. In any chat, ask the assistant for something that needs your approval in that chat's mode. For example, in Ask mode: "Write hello into a file note.txt in your folder".
    2. Before it asks, close the window to the tray.
    3. Expect one notification named Gathr, with the chat's title and "<assistant's name> needs your approval", and no sound.
    4. Click it while it is on screen. Gathr opens on that chat. Approve or deny there, then switch to another window within 3 seconds. Ask again: one notification.
    5. Repeat with the window open and in front: no notification.
    6. In the team chat, while it has a question open for you: open Gathr, look at it, close the window, and have an agent there ask something that needs your approval. Expect one notification. Without opening Gathr, let a second one come up: no second notification. Open Gathr, close it again, and let a third come up: one notification.
    7. Tray > Pause all, close the window, ask again: no notification. Tray > Resume all: one notification, "Resumed", "1 chat needs you".
    8. Tray > Quit with a chat that needs you. Open Gathr from the Start menu and switch to another window within 3 seconds: one notification for that chat, or "Waiting on you" with the count.
    9. In PowerShell: `& "$env:LOCALAPPDATA\Gathr\gathr.exe" diag query "SELECT time, attrs FROM event_log WHERE name = 'gathr.ui.notify' ORDER BY ts DESC LIMIT 10" --text`. With no `--data` it reads your own folder, which is the point here.
    10. If no notification came at all: Windows Settings > System > Notifications, and see whether Gathr is listed and on.
  - **The owner's check on macOS,** on `/Applications/Gathr.app`, the same steps with these differences:
    1. Update with the blue Update on the rail.
    2. The first notification may first ask whether Gathr may send notifications: choose Allow. Whether macOS asks isn't verified. If nothing shows, or it was refused: System Settings > Notifications > Gathr, and turn Allow notifications on. Note whether the notification is named Gathr or Terminal.
    3. Steps 1 to 6 as on Windows. Closing the window hides it in the menu bar. Note the name and icon the notification shows, and whether it was silent.
    4. Step 7 with the menu bar icon's Pause all and Resume all.
    5. Step 8: Quit from the menu bar icon's menu (closing the window doesn't quit), then open Gathr from Applications and switch to another app at once.
    6. Step 9 in Terminal: `/Applications/Gathr.app/Contents/MacOS/gathr diag query "SELECT time, attrs FROM event_log WHERE name = 'gathr.ui.notify' ORDER BY ts DESC LIMIT 10" --text`.
  - A step that fails on either is a fix in a follow-up PR, with the event lines from the query.
