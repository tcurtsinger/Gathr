# Use the window

Part of [AGENTS.md](../AGENTS.md)'s Run, use and check it; the other parts are listed there.

- **Chats and projects in the window:** New (or a project's + in the sidebar) opens a draft, and the chat is made at its first send, in the project picked above the composer. New project, last in that picker, takes a name, a git folder and up to 5 agents with their roles. A project's More in the sidebar has Project settings, which opens Settings > Projects at it: General (name, folder, team) and Checks & merge (its checks read only, the CI choice and merge method) save with one Save. Checks are set only by an agent's tool, so to see some on test data, insert rows into `project_checks` with the service stopped. A chat with more than one member shows every agent's turns in the one timeline (0037: a turn is one block, its work folded into the row above its message) and Summary in its header (0038): the button is the initials of whoever is working, with a dot when someone needs you, and it opens the Supervisor's current round as Plan (the tasks of its newest hand-off, by `given_in`) over one line for each agent. The Working line after the latest message opens it too. A step, an agent's line, or an agent's initial in the timeline opens that agent as a tab in the workspace: its task, its running turn's row, its earlier blocks and its tasks, with Message to send to it. The recipient picker lists the Supervisor first; to see a round without a login, give tasks through the tools with the replay engine held, as in Tasks and waits ([api-tasks.md](api-tasks.md)). The replay engine plays its recording once per process and Gathr reuses an engine for an agent's next turn, so for several turns repeat the recording's rows once per turn.
- **Archive, Delete and stale in the window:** the chat header's More menu and each sidebar row's have Archive (Restore once archived) and Delete, each asked first. Archived chats are in the folded Archived group at the foot of the sidebar and open read only, with Restore. The Tasks list groups stale ones under Stale; an agent's stale task opens in its chat's Tasks tab with Cancel and Restart. To see stale tasks on test data, start the service with `GATHR_STALE_DAY_MS=15000` and `GATHR_WAIT_EVERY_MS=2000`: the seed's open tasks go stale in about a minute. Settings > General has the two day counts.
- **Search in the window:** Search under New, or Ctrl K (Cmd K on macOS), searches chat titles and saved messages across chats (0035); the query stays between openings. Up and Down move one cursor over Chats then Messages, Enter opens the row. A message hit opens its chat centred on that message (a turn's row opens for words it wrote mid-work), tinted briefly and focused, and the view holds there until the person scrolls back to the bottom or sends: `gathr.ui.search.open` times it, `gathr.ui.search.error` records a failed search with its `ref` or a hit no longer in its chat. Seeded text repeats about 40 words, so every long message matches most queries: to try a hit far up a chat, add a distinctive word to one message in a stopped test folder's database (the index follows an `UPDATE` of `body`).
- **Pause and stop in the window:** the chat header's More menu has Pause, then Resume, or Restart after a stop; the composer's Stop while a turn runs is Stop now for the chat. Pause or resume at the foot of Summary pauses or resumes one agent alone, and the tray has Pause all and Resume all. While paused or stopped, a quiet line after the latest message says so. The replay engine takes an interrupt only while it streams, so to try Stop now on a held round, let it stream first.
- **The person's questions in the window:** Tasks under New lists every open question across chats (`--seed` adds six; seed a folder several times for dozens). Picking one opens its chat's workspace (the header's sidebar toggle) at that question in the Tasks tab: Back and Next keep drafts, Send on the last sends every ready answer, and a refused one stays open with its reference. A question's file opens as a tab beside Tasks. To force a refusal, block a window's live socket, cancel the question with `POST /api/tasks/<n>/cancel`, then Send it there.
- **The window's title bar follows Theme** (Settings > General): the page calls the window's `set_theme`, the one command its IPC allows, and only from `http://127.0.0.1` (`crates/gathr-app/capabilities/theme.json`); a refusal is a `gathr.ui.window.theme` error. To check System, drive the window without `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port`: with it, the page always reads the system as light.
- **The window updates itself** (F7): a release build checks `latest.json` at start and every hour, downloads the update and checks its signature, then installs it at once if the window is hidden in the tray, else when it's next hidden; meanwhile the tray menu has Restart to update. Only the window restarts, hidden again if it was; the service keeps running. When the service hands over to its own update, the window signs in to the new one by itself (`gathr.ui.window.follow`); when the service stops answering for 3 s while the window is open, the window starts it again the way a launch does, so a new copy that died on trial rolls back at once (`gathr.ui.window.restart`; a failed restart goes to the crash log). A window showing Start failed tries the same every 3 s, so it takes up a folder an old service let go of without a relaunch; to check, hold `<data>/gathrd.lock` from another process while it opens, then release it. To stop a test service for good, quit or stop the window first. A debug build never checks. Events are `gathr.ui.update.check` and `gathr.ui.update.install`. To try one locally: build two versions with `release.mjs` and the Tauri CLI, adding a `--config` whose `plugins.updater` has your own test key's `pubkey`, `endpoints` `["http://127.0.0.1:47199/latest.json"]` and `dangerousInsecureTransportProtocol: true` (sign with that key in `TAURI_SIGNING_PRIVATE_KEY`, never the real one), with `GATHR_APP_FEED=http://127.0.0.1:47199` set so the service checks the same feed; serve the newer one's folder after `release.mjs feeds <version> <folder> http://127.0.0.1:47199` on that port; install the older one with `<setup>.exe /S /D=<folder>` (it also adds a desktop shortcut: delete it, and run `uninstall.exe /S` when done), and open it with `--data`. A PR's build artifact does the same with the real key.
