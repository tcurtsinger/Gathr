# The API: engines, accounts and agents

Part of [AGENTS.md](../AGENTS.md)'s Run, use and check it; the other parts are listed there. The API's address and sign-in are in [api.md](api.md).

- Engines and git get the person's current PATH: read again from the registry on Windows, from the login shell on macOS. The engine's start event says where it came from (`gathr.env.from`).
- Gathr's own updates ([0032](decisions/0032-service-updates.md)): `GET /api/app` (the version that runs, the one before, `state`, the last check, `failed` with its `ref`, `update` while it holds; live as `{"type": "app"}`), `POST /api/app/update` checks now. Each release's `gathrd.json` names its archive; `GATHR_APP_RELEASES` names another feed (a debug build has none), and `GATHR_APP_HOLD_MS` shortens the 30-minute hold, in dev and tests only. A build made with `GATHR_APP_FEED=<address>` set checks that feed instead of GitHub's, with no variable at run time: build a test release that way to try an update on an installed Gathr exactly as a real one runs. Events are `gathr.app.update`, `gathr.app.hold`, `gathr.app.switch` and `gathr.app.handover` (where the last hand-over got to, from `app/handover.json`). To force a stopped hand-over, write that file with a `step` other than `starting the update` in a stopped test folder, start it, and trace the reference `diag failures` gives. The replay engine's `GATHR_REPLAY_CHILD` leaves a child holding its output after the engine is killed, as in the 0.1.39 hang.
- Codex models (0033): Engine default, Gathr-owned Family Latest rows, then exact models, all from the account's catalog. Latest IDs are `latest:<family>`; numeric `gpt-<version>-<lowercase family>` names group automatically, unfamiliar shapes stay exact. Each new engine session resolves the alias against all model-list pages before opening the thread.
- Codex (0033): `GET /api/engines/codex` and `POST /api/engines/codex/update` match Claude's copy state. Its npm platform archive is SHA-512 checked, with the full `vendor/<target>` retained. `GATHR_CODEX_RELEASES` names another npm metadata feed in dev and tests; `GATHR_CODEX_PATH` stands in for the owned executable. A debug build downloads nothing unless a feed is set.
- Claude Code: `GET /api/engines/claude` (where it was found, Gathr's copy). `POST /api/engines/claude/update` checks the release feed now. Settings has no path: `GATHR_CLAUDE_PATH` in the service's environment stands in for Gathr's copy, in dev and tests only (the replay engine, or a missing file for a forced failure).
- Accounts: `GET /api/accounts`, `POST /api/accounts {"engine": "claude", "name"}`, `GET /api/accounts/<id>`, `PATCH /api/accounts/<id> {"name"}`, `DELETE /api/accounts/<id>` (signs it out, closes its engines gently and deletes its folder; one that reads signed out needs no Claude Code, and on macOS with no Claude Code the sign-in state is its Keychain item). Names are unique, ignoring case. Each account's login is in `<data>/accounts/<id>/claude`. A new data folder has no accounts; a message sent to no agent runs on the oldest one.
- Codex accounts: add with `{"engine": "codex", "name"}`. Each owns `<data>/accounts/<id>/codex` as its `CODEX_HOME`, never the person's `~/.codex`. The same sign-in route starts the browser by default; `{"device": true}` starts a device code (beta, enabled in ChatGPT first). Both finish through `account/login/completed`, with `paste: false`; Claude sends `paste: true`. `BROWSER` names a test program when a real browser must not open. The replay engine enters Codex mode for `app-server`: `fail-login` in the account's Codex folder forces a failure, `hold-login` holds it for switching/cancelling. Remove either file after the check.
- Models: `GET /api/accounts/<id>/models` lists the account's models (`id`, `resolved`, `latest`, `name`, `description`, `efforts`) as its engine reports them; `latest` marks a family alias such as `opus`, which moves to each new release. Claude Code lists its newest models by family only (`opus`, named "Opus 5.5" signed in), so each family row is followed by a row for the exact model it means today (`claude-opus-5-5`, `latest: false`, the same name and efforts): the id an agent is saved with. Settings > Agents offers only the exact models, in the engine's order, never `default` or a `latest` row (the owner, 2026-11-12: a model is chosen and changed by hand); a new agent takes the exact model the engine's default means. An agent saved before on a family, a `latest:<family>` or the engine's default keeps running as it did and reads "Opus 5.5 / Latest" or "Opus 5.5 / Engine default" until a model is picked for it. The replay engine answers with `tests/frames/initialize.json`.
- Agents: `GET`/`POST /api/agents {"name", "account", "model", "effort", "approvals"}`, `GET`/`PATCH`/`DELETE /api/agents/<id>`. A `null` model or effort is the engine's default; one the account's engine doesn't list is refused. A new account clears the model and effort the same change doesn't set. A change applies from the agent's next turn. An account isn't removed while agents use it (409). Each agent shows `hold` (`why`, `pid`, `since_us`) while its engine hasn't exited 30 s after a gentle close; the live socket sends `{"type": "hold"}` when it starts and ends.
- Engine times: an engine closes the gentle way to switch chats, accounts, model or effort, and after 10 idle minutes; it's never killed except at shutdown. A stop ends an engine's open `GET /mcp` stream at once (its calls still get their answers) and waits 15 s (the engines' 10 s close grace and 5 s) for other requests under way, then goes on without them (`gathr.service.connections`, with how many were open). `GATHR_HOLD_AFTER_MS` and `GATHR_IDLE_CLOSE_MS` in the service's environment shorten the 30 s hold and the 10 minutes, in dev and tests only.
- Sign in: `POST /api/accounts/<id>/sign-in` runs `claude auth login` in the account's folder and answers its page's `url`; `POST …/sign-in/code {"code"}` passes a pasted code; `DELETE …/sign-in` cancels. `POST /api/accounts/<id>/sign-out` runs `claude auth logout` there. The replay engine answers both for Claude: `made-up-code#…` signs in, any other code fails. To keep a real run from opening your browser, set `BROWSER` to a script that only logs its argument. Without it, links open through the system (`rundll32 url.dll,FileProtocolHandler` on Windows, never `explorer.exe`, `open` on macOS): `cargo test -p gathr --test open_browser -- --ignored` checks a long sign-in link reaches the real browser whole (it opens a tab).
