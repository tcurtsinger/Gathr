# The API: tasks, pauses, archive and the agent folder

Part of [AGENTS.md](../AGENTS.md)'s Run, use and check it; the other parts are listed there. The API's address and sign-in are in [api.md](api.md).

- Tasks and waits ([0010](decisions/0010-coordination-as-state.md)): agents give and settle them only through Gathr's tools ([api-approvals.md](api-approvals.md)). `GET /api/chats/<id>/tasks` lists the chat's tasks (each with `given_in`, the turn that gave it, and `round`, the turn the person's message or answer began that this work answers: [0051](decisions/0051-the-giver-hears-when-all-is-in.md)) and its waits; `POST /api/tasks/<n>/cancel {"why"}` and `POST /api/tasks/<n>/restart` are the person's. A fix Gathr gave after a review ([0053](decisions/0053-a-review-asks-both-questions.md)) carries `by_gathr: true` (left out on every other task): its `giver` stays the reviewer, who hears back on it, but Gathr gave it, and the window names Gathr. A task also carries its brief ([0059](decisions/0059-a-work-task-carries-a-complete-brief.md)): `done`, `proof`, `where`, `size` and `lines` (each left out when empty), and, once its giver has changed it before it started, `edited_us` and `edited` (the names of the fields the last edit changed: `what`, `why`, `done`, `proof`, `where`, `size`, `after`). Gathr keeps when it started and its queued brief's carry, and doesn't send them. Only its giver changes a task, with the `edit_task` tool, until its first turn starts; the person doesn't edit one. Each turn in `GET /api/chats/<id>` carries its `task`, and what Gathr told an agent (a task, a wake-up, a hear-back) is a message with role `gathr`. A task that ends done is one too, with no turn (`turn` null), said when it ends and sent on the live socket as any message: its first line is "A task is done:", its second the task as a hear-back names it. A giver's hear-back turn comes at once for a task that ends blocked, failed or stopped, and otherwise when everything it gave from the same task, or with no task in the same round, has ended; none comes when all of it is done and the giver's own task is held and reported done (0051). A `wait` with `pr` and `up_to_date: true` is met once that PR has every commit its base has (GitHub's compare: `behind_by` 0), or it merges or closes (0043 C12; kind `up_to_date`). A wait that isn't met keeps what its last look saw (`seen`) and when (`looked_ts`): for CI, each check as it stands, "1 of 2 checks on #5 at 0123456 finished: 1 passed; queued: UI (macOS)"; for a PR, that it is open; for an up-to-date wait, how far behind; for a check, its exit code and what it printed (its first 300 characters, with secrets hidden). A wait of several parts gives each part's. `list_tasks` shows it to the wait's agent as "Last look: …", with the error of looks that failed. A CI check is queued, running, passed, failed, cancelled, skipped or unknown (a conclusion Gathr has no word for, never counted as passed), and the wake names the ones that failed, were cancelled or are unknown: a job GitHub cancelled isn't a failed test (G144, G181). CI has finished once every check has, whatever each came to. The service looks at open CI, PR, up-to-date and check waits, and tasks' PRs, every 2 minutes; `GATHR_WAIT_EVERY_MS` in the service's environment shortens that, in dev and tests only. `gathr diag health` lists open tasks and waits; events are `gathr.task.*` and `gathr.wait.*`. To try it without a login, hold the replay engine (`GATHR_REPLAY_HOLD`), take a token from `GATHR_REPLAY_ENV`, and call the tools as in `tests/coordination.rs`; a recording's `{"dir": "hold", "line": "take"}` row uses the hold file up, so each one you make lets one held turn on, for a round of several agents in order. `cargo test --test <name>` doesn't rebuild the replay engine: `cargo build --example replay_engine` after changing it.
- Asks and their size ([0061](decisions/0061-every-ask-has-a-size.md)): in a team chat (two or more agents) the person's message starts an ask or joins one, and every turn and task records the ask it serves. `GET /api/chats/<id>/tasks` and the live `tasks` event ([api.md](api.md)) carry `asks`, oldest first, each `{"id", "title", "size", "by", "sized_in", "held"}`: `id` is the id of the message that started it, `size` is `repair`, `new` or null (not sized: it counts as new), `by` is the lead's agent id or `person`, and `sized_in` is the lead's turn that sized it, null when the lead never did; and each task carries its `ask` (left out when none), and each ask carries `held`: true once Gathr refused a building give, a write or a push of it ([0063](decisions/0063-building-waits-for-a-new-asks-plan.md)), which makes an unsized ask's size line show. Turns in `GET /api/chats/<id>` don't carry it: `gathr diag query "SELECT id, ask_id FROM turns"` reads it. `POST /api/asks/<ask>/size {"size": "repair" | "new"}` is the person's: it answers the ask as the list has it, and is refused with 409 `Size failed` and a reference for an ask that doesn't exist (`there's no ask <id>`), a size that isn't one, and an archived chat; the same size again writes nothing. The lead sizes with the `size` tool ([api-approvals.md](api-approvals.md)). Open work, the split and when Gathr says "Fixed" are in the decision. When a repair's work is in, Gathr says one line in no turn, once, sent on the live socket as any message, after the "A task is done:" line: "Fixed: <the ask's title>", then one line for each done work task, `#<n> <what>: PR #<pr>. Proof: <proof>` (the PR, else what its report names, else nothing; the proof when it has one). Events: `gathr.ask.message` (`gathr.ask.id`, `gathr.message.id`, `gathr.turn.id`, `gathr.ask.joined`) on a person's message's trace; `gathr.ask.resized` (`gathr.ask.id`, `gathr.ask.size`, `gathr.ask.was`, `gathr.ask.by`, `gathr.ask.correction`, and for a split `gathr.ask.split`, `gathr.ask.from`, `gathr.turn.moved`, `gathr.task.count`; `gathr.turn.id` for the lead's call); `gathr.ask.fixed` (`gathr.ask.id`, `gathr.message.id`, `gathr.task.count`), which records `error("sqlite")` and why when its check fails. A database from before migration 0046 has no asks: its turns and tasks serve none, and the first message after the upgrade starts one. Corrections for scorecard 1: `gathr diag query "SELECT count(*) AS corrections FROM event_log WHERE name = 'gathr.ask.resized' AND attrs ->> '$.\"gathr.ask.correction\"' = 1" --data <folder>`. Deleting a chat deletes its asks. To try it without a login, hold the replay engine and call `size` with the lead's token, as in `tests/sizes.rs`.
- The hold ([0063](decisions/0063-building-waits-for-a-new-asks-plan.md)): in a chat of two or more agents, a turn is held when its task is a look-into task, or when its task isn't a building task and the ask it serves isn't a repair (`size` `repair`; no size counts as new) and has no approved plan. A building task is a work task that isn't a look-into task, and its turns are never held, so running work isn't stopped; a turn that serves no ask (a wake, a silent turn, a stale-tasks turn, a PR handed to its reviewer, a compaction, a turn from before migration 0046) is not held, and a chat of fewer than two agents holds nothing. Nothing stores it: each reader asks when it acts, so Approve, a resize or a split changes it for a turn already running. A task has `look_into` (true for a task given with `look_into`, left out when false); it is held for its whole life, after Approve too, its brief carries a line that says it only looks into something (0056's `brief` is at version 3) and its report names no PR. A building task that has not started and sits on a held ask is `waiting` with the reason `waits for its plan`, with no turn, whether it was given, readied again, released by a dependency or restarted. A resize of the ask (`POST /api/asks/<ask>/size`, the lead's `size`, a split, or Approve) moves what is not started: held now, a `ready` task's queued turns are marked stopped ("its task #2 waits for its plan") and it waits for the plan; not held now, what waited goes back in line. A started task and its turns aren't touched. The person's resize also tells an agent, by a turn of a new kind of Gathr's words, `resized` (0056, version 1, `ask_id` the resized ask): to new from a repair, to the Supervisor when the ask has open work, naming the tasks that wait; to repair, to the agent the ask's message went to when Gathr held something of the ask or tasks went back in line, naming them. The lead's own `size`, a split and Approve tell nobody. `POST /api/asks/<ask>/size` starts the turns the change releases. Events: `gathr.hold.refused` (a refused give, write or push: `gathr.ask.id`, `gathr.turn.id`, `gen_ai.agent.id`, `gathr.hold.what` `give`, `write` or `push`, `gathr.hold.why` `unplanned` or `look_into`, `gathr.hold.plan` `checking`, `waiting` or `revising` when the ask has an open plan, `gen_ai.tool.name` for a give or a write), `gathr.hold.read` (the hooks couldn't read the hold in 5 s or at all: `error` `timeout`, `writer` or `sqlite`, `why`) and `gathr.hold.wait` (`gathr.ask.id`, `gathr.hold.how` `held` or `released`, `gathr.task.count`, recorded when a task moved). A task waiting for its plan is a line of what the chat waits on (`kind` `plan_wait`, "#5 (Ann) waits for its plan", `moves` `others`, on the Supervisor) in place of the `idle` line: it never wakes the lead, and with nothing else moving the person is told by it after the tell time. The stale sweep marks such a task stale but doesn't cancel it while its ask has an open plan (checked, waiting on the person or being revised); with no plan, it is cancelled as any waiting task is. The catch: a held turn's worktree is read from what git tracks when the turn starts and when it ends (`gathr::hold::look`, `turns/hold.rs`), so what a shell command or Codex changed, which Gathr can't refuse, is found. Only a held turn in a project's chat whose agent has a worktree is looked at; the start is kept in `held_turns` (migration 0049), so a service stopped mid-turn loses nothing and the agent's next turn there first looks at its earlier turns still unlooked. A change is an entry added to or gone from `git status --porcelain -z --untracked-files=normal`, a listed file whose content id (`git hash-object --no-filters`) changed, or a file of a non-merge commit the turn made that no remote-tracking ref holds; a head that only moved (a pull, a checkout to read) is none, and ignored files aren't listed. The look runs `core.fsmonitor=false` and asks the rule again at the end: a turn released meanwhile ("Just fix it.", a resize to repair, Approve) reports nothing. More than 2,000 entries at the start and nothing is kept. A change is one of Gathr's lines in the held turn: "<agent> changed 3 files before the plan was approved" ("1 file" for one; "<agent> changed 3 files on look-into task #12"), one line per file, sorted, at most 20, "and <k> more", and "Committed: <c>" when some came from commits. The ask's `held_ts` is set with it. The tasks answer and the live `tasks` event carry `caught`, the message ids of these lines, oldest first (a trigger on `held_turns.line` notes the chat), so a window draws them as kind `changed`, not as a note. The agent's next turn, when still held, opens with "In your last turn you changed 3 files in <worktree>: a, b, c. The person sees them." and the reason for its hold, after the opening of a fresh conversation and before Gathr's text; it is no kind of words (0056). Every catch not told yet is marked told. Events: `gathr.hold.look` (`gathr.turn.id`, `gen_ai.agent.id`, `gathr.hold.at` `start` or `end`, `gathr.hold.entries`, `gathr.hold.duration_ms`; `error` `git`, `too_many` or `sqlite` with `why`; `gathr.hold.released` true for a turn released mid-turn), `gathr.hold.changed` (`gathr.ask.id`, `gathr.turn.id`, `gen_ai.agent.id`, `gathr.task.id` for a look-into task, `gathr.hold.files`, `gathr.hold.count`, `gathr.hold.committed`, `gathr.message.id`) and `gathr.hold.told` (`gathr.turn.id` told in, `gathr.hold.of` the turn caught). A failed look is found from the turn's reference with `gathr diag trace <ref>`. The count: `gathr diag query "SELECT count(*) AS caught, sum(attrs ->> '$.\"gathr.message.id\"' IS NULL) AS unshown FROM event_log WHERE name = 'gathr.hold.changed'" --data <folder>` (aim 0 and 0). It misses what a turn that became held only mid-turn, or an engine-begun turn before Gathr set it running, changed; a file inside an untracked folder that already existed; a merge commit's own content; and it reports commits checked out from outside the remote-tracking refs (a PR head in `FETCH_HEAD`) and a pull's conflict left in the status. Nothing is undone. The refusals by kind: `gathr diag query "SELECT attrs ->> '$.\"gathr.hold.what\"' AS what, count(*) AS n FROM event_log WHERE name = 'gathr.hold.refused' GROUP BY 1" --data <folder>`. To try it without a login, hold the replay engine, take a token from `GATHR_REPLAY_ENV`, and call `give_task` and the hook as in `tests/hold_flow.rs`.
- Plans ([0062](decisions/0062-a-plan-is-checked-and-approve-hands-it-out.md)): the lead writes a plan with the `plan` tool ([api-approvals.md](api-approvals.md)), and each call is a version, the lead's own message in its turn. `GET /api/chats/<id>/tasks` and the live `tasks` event carry `plans`, oldest first, each `{"id", "ask", "title", "lead", "state", "versions": [{"id", "n", "message", "parts", "check_line", "sent", "decided", "decided_line"}]}`: `state` is `checking`, `revising`, `waiting` (on the person), `approved` or `dropped`, read from the newest version and its check, never stored; `sent` is when the version reached the person (UTC text, null while its check runs or after it left findings); `decided` is `approved`, `sent_back` or `dropped`; `check_line` and `decided_line` are the ids of Gathr's lines. Each task carries `checks` (the version it checks) when it is a plan's check, and `plan` (the plan whose part made it) when Approve made it, each left out when none. `GET /api/plans/<plan>` answers the summary plus `changed` (the caught turns of the plan's ask, oldest first: `agent` (an agent id), `files` and `message`, Gathr's line, always present, empty when none, 0063), `asked` (the ask's message), `questions` (`number`, `what`, `answer`: the ask's questions to the person) and, per version, `title`, `text`, `created`, `words`, `answers` (`note`, `changed`, `why`), `check` (`task`, `by`, `state`, `outcome`, `notes`: `agrees`, `findings` or `unfinished` once settled, `findings` staying after a newer version or the person cancels it, `late` while open after the version was sent, else null) and `parts` (`n`, `owner`, `what`, `why`, `done`, `proof`, `where`, `size`, `lines`, `after`, `after_tasks`, `task`). The person's word: `POST /api/plans/<plan>/approve {"version"}`, `.../send-back {"version", "words"}` and `.../drop {"version"}`, each answering the summary. Each refuses, with a 409, an error (`Approve failed`, `Send back failed`, `Drop failed`; `Plan failed` for the read) and a reference, for a plan that isn't there, an archived chat, a version that isn't the newest, one already decided, and (Approve and Send back) one still being checked, a lead that no longer leads the chat, empty words, a part whose owner has left the chat or a part that comes after a cancelled task. Approve makes one work task of each part, word for word, in one transaction and starts those with nothing to wait on, with no turn of the lead's; Send back queues a turn for the lead; Drop ends the plan and starts nothing. Events, each on the request's or the tool's trace: `gathr.plan.version` (the plan, its version and ask, the message, the part count, the check task and its checker), `gathr.plan.checked` (`gathr.plan.outcome`: `agrees`, `findings`, `unfinished` or `late`; `gathr.plan.sent`) and `gathr.plan.decided` (`gathr.plan.how`: `approved`, `sent_back` or `dropped`, and for an Approve `gathr.task.count` and `gathr.task.started`). Gathr says one line in no turn when a check ends ("Bo agrees with version 1 of the plan ...", "Bo has 3 findings on ...", "Bo didn't finish checking ..."), when a plan is approved ("Approved: version 2 of the plan ..., 3 tasks.") and when it is dropped; a send-back is a message that opens the lead's turn. A version still checked 10 minutes after it was written (`GATHR_PLAN_CHECK_MS` changes the time, in dev and tests only) is said "didn't finish" at the next quiet look, so it reaches the person 10 to 12 minutes in. A check can't be cancelled, restarted or edited by an agent: `cancel_task` says it is a plan's check and `restart_task` and `edit_task` refuse it. The person's cancel from the Tasks tab stays, and the version then reaches them as "didn't finish". A done, failed, stopped or cancelled check wakes the lead no more than any other; a check left with findings does. A waiting plan is a line of what the chat waits on (`kind` `plan`, "A plan for you: <title>", moving to you), a reason for the chat's `needs` and for B's notification. An open plan is open work of its ask ([0061](decisions/0061-every-ask-has-a-size.md)), and a split never moves a plan, its check or the tasks Approve made.
- Which conversation a turn runs in ([0055](decisions/0055-a-members-task-starts-in-a-new-session.md)): nothing in the API sets it; Gathr reads it from the turn when it starts. A member's turn on a task runs in that task's conversation (kept in `task_sessions`, one row for each task and agent, with the account and the context it last filled). The first turn on a task opens a new conversation, given the ask and the agent's last five other tasks in the chat; later turns on it, a restart, a carry-on, a wait on the task, a hear-back that answers a turn on it and Gathr's fix for its PR's work task resume it. A review and a second look each start new. The lead's turns, the person's and a teammate's message, a wake, a compaction and a wait with no task run in the agent's latest conversation. A turn on another conversation than the engine's closes it first (`gathr.engine.close`, `the next turn is on another task`), except while a background command runs (`gathr.session.kept`). `gathr.engine.start` shows `gathr.task.id`, `gathr.session.for` and `gathr.session.from`; `gathr.session.opening` and `gathr.engine.resume_failed` are on the turn's trace (`gathr diag trace <ref>`). A conversation the engine refuses to resume is forgotten, the engine closes (`gathr.engine.close`, `it couldn't resume its conversation`), and its turn starts again, once, in a new one. Deleting a chat deletes its rows; archiving keeps them.
- The person's tasks (F9, [0010](decisions/0010-coordination-as-state.md)): only a chat's Supervisor (or a chat's only agent) gives them, with `ask_person`; from a member it becomes a `person_request` task for the Supervisor, who files it in its own words (`for_task` and a `what` of its own: without one the ask is refused), folds it into one the person has (`finish_task blocked` with `on_task`: the member isn't told it's blocked, and the request is readied with the answer in its carry when the question is answered), or answers it ([0065](decisions/0065-questions-in-the-leads-words.md)). The person's answer settles the request the question was filed for in the same transaction (the request is `done` with the reason `the person answered #<q> (<what>): <answer>`), and its member hears at once; the Supervisor hears too, in its answered turn. `finish_task blocked` on a request with its question still open (`ready` or `held`) is refused. A person task has `owner: null`, kind `person`, a `form` (`done`, `yesno`, `choice`, `choices`, `text`), `choices` (`label`, `detail`; the asker's pick first) and `files` (copies made when asked, read at `GET /api/tasks/<n>/files/<i>`, served with `Content-Security-Policy: sandbox`). `GET /api/person-tasks` (`?chat=<id>` for one chat) lists the open ones, oldest first, each with `chat_title` and `for_agent`; `POST /api/person-tasks/answer {"answers": [{"task", "pick", "yes", "done", "text", "discuss"}]}` takes each answer or refuses it on its own (`{"answered", "refused": [{"task", "why", "ref"}]}`); words alone answer any form. What agents hear keeps the pick and the words apart (`Picked: Connection lost. Their words: and say we retry`, with ` (answered by <name> for the person)` when an agent answered for them); the task's own `reason`, which the window shows, stays the merged line. With `discuss: true` and `text` alone, the question isn't answered: it goes to `held` (also in the response's `answered`, in that state), leaves `GET /api/person-tasks`, the chat's `needs` and the plan's wait, and the words reach the Supervisor only, as its turn under `The person wants to discuss:`; the task's `answer` is `{"discussed": [{"text", "turn", "at"}]}`, kept when it is answered later; `at` is when it was sent, in microseconds ([0073](decisions/0073-gathr-speaks-as-a-speaker.md)). It is refused, with a reference, with no words (`Discuss #<n> with a message`), with a pick, yes or done (`Discuss #<n> with a message alone, not a choice`), on a question that isn't `ready`, and on Gathr's own question; an agent's `answer_person` never discusses. The question is `ready` again, as it was, when the turn that heard it ends (done, failed or stopped) and at a start for a turn no longer to come; a question the same Supervisor asks in that turn for the same request cancels it (`#<new> took its place`) and takes what was folded on it. Events: `gathr.task.discussed` (`gathr.discuss.how` `asked`, `back` or `replaced`; `gathr.turn.id` on `asked`, `gathr.task.question` on `replaced`) and `gathr.task.request` (`gathr.task.question`, `gathr.request.how` `answered`); `gathr diag query "SELECT attrs ->> '$.\"gathr.discuss.how\"' AS how, count(*) FROM event_log WHERE name = 'gathr.task.discussed' GROUP BY 1"` counts them. Each Send wakes each asker once (`gathr.task.answered`), and each task it settled gets that wake-up's turn as `heard_in`, An answer keeps what was sent and when, `{"pick", "yes", "done", "text", "by", "at"}` with `at` in microseconds, which the chat shows as the person's own message at that time; one sent before 0073 has no `at` ([0073](decisions/0073-gathr-speaks-as-a-speaker.md)).task.answer`.
- Gathr's question to the person ([0054](decisions/0054-a-change-past-the-far-end-waits-for-the-person.md)): a PR that adds more lines than the project's line (the most any of its last 50 changes added, never under 3,000) is asked about before it lands, with a person task Gathr gives itself: `giver` and `owner` null, kind `person`, `ready`, form `choice`, `pr`, `parent` the earliest work task on the PR in the chat that isn't cancelled, and the choices `Let it go on` and `Send it back` (nothing recommended). It is in `GET /api/person-tasks` like any other and the window shows its asker as Gathr. Only the person answers it, with exactly one pick: an agent's `answer_person` is refused with `#<n> is Gathr's question to the person: only the person answers it`, an answer with no pick or two with `Answer #<n> with one of its choices`, and a pick it doesn't offer with `#<n> has no choice <pick>`, each a refusal in `gathr.task.answer` with a reference. `Let it go on` lets that count through and Gathr looks at landing at once; `Send it back` blocks the parent work task with the reason (`The person sent #5 back as bigger than asked: ...`), its giver hears, and the PR rests at that head until a new one. The question is cancelled when a later measure finds the PR no longer over, when the PR merges or closes, or when the chat is archived. Events: `gathr.change.asked`, `gathr.change.answered` (`pick`), `gathr.change.withdrawn`. Turns on the PR's tasks aren't held while it is open or after a send-back. `restart_task` on a blocked task carries its reason into the brief, as it does for a stopped or failed one. The waiting answer says `#5 to land: waits on your answer to #<n>` (waits on you), `#5 to land: you sent it back; waits on a new head` or `#5 to land: you cancelled #<n>; waits on a new head` (others).
- Gathr's question when a task reports done ([0064](decisions/0064-a-change-far-past-its-fix-or-its-part-stops-and-asks.md)): `finish_task` with `how` `done` counts the PR it names before the report is written, when the report first names the PR (or reports it again after a send-back) from the caller's own building task (a work task that isn't a look-into task), no review covers the PR yet, the chat has a project and the task has a line. A task on a repair ask has the Fix's line: the most any of the project's last 50 landed Fixes added, never under 1,000 (1,000 under 10). A task on a new or unsized ask with `size_lines` has `max(3 × size, size + 300)`, so a part of 100 lines is asked about past 400 and one of 500 past 1,500; a task with no ask, or on a new or unsized ask with no size, has none and is not counted. The count is landing's own (api-checks.md), in the project's folder under its lock, within 20 seconds (`GATHR_REPORT_COUNT_MS` shortens it, in dev and tests only). Past the line the question is 0054's with `given_in` set: the turn the review would be given in (the report's, else the task's newest), so the task waits on it, `held` with the reason `done, waiting on #<n> (the person), #5 to merge`, and nobody reviews until the person answers. The title is `#5 adds 1,240 lines, over a Fix's line of 1,000: let it go on?` or `#5 adds 1,240 lines, over its part's line of 900: let it go on?`, its first line of why ends `A Fix's line is 1,000, the least it can be.`, `A Fix's line here is 1,400: the most any of this project's last 50 Fixes added.` or `Its part said 300 lines; its line is 900.`, and `Let it go on` has the detail `Its review starts.` A report under the line gives the review as before. The tool's answer adds a line: `Gathr asked the person about #5's size (#<n>). Its review waits for the answer.`, or, when the head rests on the person's word, the task is blocked with `#5 was sent back by the person at <short commit>. Push a smaller change, then report #1 done.` and that is the line. Asked once: another report naming the PR while the question is open adds none and gives no review. `Let it go on` settles the task as `done, waiting on #5 to merge` and gives the review, and landing doesn't ask again about that count; `Send it back` is as above, and the next done report at the same head is blocked again, at a new head it is counted afresh. The person cancelling the question (`POST /api/tasks/<n>/cancel`) rests the PR at that head (`gathr.change.answered` with `pick` `cancelled`) and blocks the work task with `The person cancelled #<n>, Gathr's question about #5's size, so #5 doesn't land at this head. Narrow #1's ask and restart it, or cancel it.`, and its giver hears. A work task cancelled while its question is open cancels it (`#1 was cancelled`), and a question withdrawn by landing or ended by the PR merging or closing releases its task. A count that fails (`github`, `git`, `not_on_origin`, `sqlite` or `timeout`) is recorded with its reference and the report goes on as it did, with the review given. Events, on the `finish_task` call's trace: `gathr.change.report` (`gathr.task.id`, `pr`, `head`, `counted`, `line`, `line_of` `fix`, `part` or `project`, `outcome` `under`, `asked` or `rested`, `duration_ms`; `error` with `why` when the count failed), `gathr.change.measured` with `by` `report` and `line_of`, and `gathr.change.asked` with `line_of` and `gathr.turn.id`. The counts: `gathr diag query "SELECT attrs ->> '$.line_of' AS line, attrs ->> '$.outcome' AS outcome, count(*) AS n FROM event_log WHERE name = 'gathr.change.report' GROUP BY 1, 2" --data <folder>`. A failed count: `gathr diag failures --since 1h --data <folder>` and `gathr diag trace <reference>`.
- Pause and stop (F10, [0010](decisions/0010-coordination-as-state.md)): `GET /api/pauses` lists each pause (`scope` `app`, `chat` or `agent`, its `target` id, `since_us`, `state` `pausing` while a turn, background command or wait check in it still runs, then `paused`, or `stopped` after Stop now, and what still `running`) and each account's usage hold (`until_us`, `kind`, its `agents`). `POST /api/pauses {"scope", "target"}` pauses; `POST /api/pauses/resume` resumes, which is Restart after a stop; `POST /api/pauses/stop` is Stop now: it interrupts the scope's turns, ends their engines' background commands with Claude Code's own `stop_task`, and queues a carry-on per agent that waits for Restart. A stopped turn's task stays as it was, `working`, with the reason `Stopped by you. Carries on at Restart`, and its giver hears nothing until the carry-on ends ([0047](decisions/0047-a-report-is-a-record.md)); only if the carry-on can't be saved is the task `stopped`. A pause holds the turns Gathr queues (tasks, wake-ups, hear-backs) and its waits' looks and checks, never the person's own message; a held turn stays `queued` with `held` (`pause` or `usage`) and its `why`, and all of it outlasts a restart. `GET /api/chats/<id>` adds `run` (the chat's own pause or the app's, else `{"state": "running"}`) and, on each member, `paused` and `usage_until_us`. A `rate_limit_event` with status `rejected` holds the account until 30 s after its reset: a turn that ran no tool is sent again then, one that did ends and a carry-on waits, its task left as it was with the reason `The account is out of usage. Carries on when it is back` (`tests/frames/usage_limit.jsonl` is made by hand: no limit was hit live). When a background command ends, Claude Code starts a turn by itself: it gets its row, on the task of the turn that started the command, and a task stays `held` while one runs. When one ends while its engine runs another turn, Claude Code says so inside that turn and begins none of its own, so the task held on it settles there and then if its owner reported it done (G174), and otherwise its owner is woken on it; with the engine idle, the turn it begins settles it. Its owner may `finish_task` a held task from any turn: the report is kept, and the task is done once the hold ends, at once if nothing is left open. An engine that exits takes its commands with it: a task held on them carries on. A turn with no progress for 10 minutes (20 during a tool) is silent: flagged once (`gathr.turn.stalled`), shown in what the chat waits on and told to its lead once (A quiet chat, below), never stopped. A turn that waits for an approval isn't flagged, and answering the approval counts as progress. `GATHR_STALL_AFTER_MS` shortens the 10 minutes, in dev and tests only. Events are `gathr.pause.*` and `gathr.usage.hold`.
- Archive and delete (F11, [0010](decisions/0010-coordination-as-state.md)): `POST /api/chats/<id>/archive` ends the chat's work in one step (its open tasks cancelled with why, waits ended, queued turns stopped, its pause gone, one `gathr.chat.archive` event), then interrupts its running turns and ends their background commands; it answers `{"archived", "ended": {"tasks", "waits", "turns"}}`. A send, a task or a restart in an archived chat is refused (409, `the chat is archived`). A turn archiving stopped stays stopped: a start under way then (its engine's version or login being read) drops it rather than leave it waiting for a sign-in, and an ended turn never goes back to `queued` or `waiting_sign_in`. `POST …/unarchive` puts it back in the list and starts nothing. `DELETE /api/chats/<id>` archives it first, closes its engines the gentle way, removes its rows, then its worktrees (their branches stay), hooks and task files: `{"deleted", "left"}`, `left` naming what couldn't be removed, with its reference. Archiving also removes the chat's worktrees in the agent folder (below), which a restored chat's next turn checks out again from their branches, but keeps a worktree with changes not committed, and a chat's folder outside a project, until the chat is deleted. Each sends `{"type": "chat", "chat", "change"}` live (`archived`, `unarchived`, `deleted`).
- Reports ([0047](decisions/0047-a-report-is-a-record.md)): a task keeps its owner's last report, and Gathr works out where the task stands from it. `finish_task {"how", "task", "note", "pr", "commit", "file", "on_task", "signed_off"}` is taken on a task in any state, from any turn of its owner's: while a turn runs on the task it applies when that turn ends (`Recorded: done. It applies when the turn running on task #<n> ends.`), otherwise at once (`Recorded: done. Task #<n> is <state>: <reason>.`). A done task answers `Already recorded`, and a cancelled one says so. With no `task`, it is the task the turn works on, or the caller's one open task in the chat; a task in another chat is refused. What is refused says what is missing: a done review with no `commit`, a review's `commit` that isn't 7 to 40 hex digits, done work with no PR, `commit`, `file` or `note`, a left with no `note`, a blocked with neither `note` nor `on_task`, a `pr` that isn't the task's own. Each task in `GET /api/chats/<id>/tasks` carries `report` (`how`, `note`, `see`: work's commit or file, `at_us`), `asked` (Gathr asked for a report and none has come) and `waiting_on` (what a held task has open). A turn that ends well never marks its task done: with nothing open and no report, Gathr queues one turn asking for it (`Your last turn on task #<n> (<what>) ended with no report.`), and after a second silent turn the task is `blocked` with `no report: two turns ended without one` and its giver hears. A task reported left with nothing open is `blocked` with `left: <note>`; its PR merging later wakes its owner instead of marking it done. A merge finishes work only if its owner reported it done; unreported work whose turn still runs is left to that turn's end. A review is done when its PR merges. A task Gathr blocks for the one it comes `after` gets that task as `blocked_on`, and goes back in line when it is restarted and finishes. `list_tasks` also lists the caller's own blocked, failed and stopped tasks. A hear-back names only the tasks its giver hasn't heard about; a task that settles as something other than what its giver last heard (blocked, then reported done) is heard once more, by itself; the same outcome again is not repeated, except after a restart, which its giver asked for. `give_task {"in_passing": true}` gives a task that isn't part of the giver's own: the giver's task isn't held on it, the hear-back on the others doesn't wait for it, and it is heard back on by itself (each task carries `in_passing`). Cancelling a member's request the person has already answered settles it as done with the answer, so what waited on it carries on. A review (`reviewed`, `outdated`, `pr_head` on its task) is out of date only when its PR's head has moved past the commit reviewed by more than clean merges of the base: Gathr's look asks git once for each pair of commit reviewed and head, by the merge tool's own rule, keeps that verdict for that pair only. When git can't say (a fetch fails, another git is at work), it keeps no verdict: the review reads out of date and the next look asks again. A review reported done is the word to land its PR ([0049](decisions/0049-gathr-lands-pull-requests.md), [api-checks.md](api-checks.md)): Gathr looks at once and the answer adds what it did or saw; `signed_off: true` goes only with a review that is done, and is kept on the task (`signed_off`). A review's report also takes `notes` and `nothing_unasked` ([0053](decisions/0053-a-review-asks-both-questions.md)): `finish_task {"notes": [{"kind", "file", "says"}], "nothing_unasked"}`, where `kind` is `wrong` (what fails against the ask), `unasked` (what the ask doesn't need) or `suggestion` (an idea for the lead, never work). A done review needs `nothing_unasked: true` and no `wrong` or `unasked` notes: `A done review says nothing_unasked: true and has no wrong or unasked notes. Report those as left.` Also refused, each with a reference: a kind that isn't one of the three, `notes` or `nothing_unasked` on a task that isn't a review, a note with no `says`, notes with no `commit`, and new `wrong` or `unasked` notes on a review already done (`New notes need a new review: ask its giver.`; a plain repeat of done still answers `Already recorded`). A review's newest report's notes show on its task in `GET /api/chats/<id>/tasks` as `notes` (`kind`, `file`, `says`). When a review settles left with nothing open, Gathr gives the owner of the first work task on that PR in the chat a task, `Fix the review of #<pr>`, from the reviewer, in passing, as a child of the review, with the notes in its why; the review settles blocked with `left: <note>. Gathr gave #<fix> to <builder> to fix it`. The fix reaches the reviewer on the review itself once it is done and held on its merge. No fix is given when no work task names the PR, when the reviewer gave one on that PR in the same turn, for `unasked` notes alone when an earlier fix already carried them on that PR in this chat, or when the give is refused; each is the event `gathr.review.fix` with its outcome (`given`, `no_work_task`, `reviewer_gave_one`, `asked_once`, `refused: <why>`). `gathr.review.notes` is written for every done review and every report with notes. A done review's suggestions follow its note in the done line, as `Suggestion: <file>: <says>`, and start no turn. A review's brief names its PR and head as last seen, the task it answers, and asks what the ask doesn't need. A reviewer records a done review again with `finish_task {"how": "done", "commit"}` on the same task while the PR is open; the task stays done, and if the commit isn't the PR's head as last seen the review reads out of date until the next look judges it. `list_tasks` shows `[reviewed at <commit>, out of date: #<pr> is at <head>]` and also lists the caller's own done reviews that went out of date. A work task's done report that first names its PR (`pr` on a task that had none), in a chat with a Reviewer who isn't its owner, gives that Reviewer `Review #<pr>` in the report's own transaction ([0060](decisions/0060-gathr-gives-the-review-task.md)): given by the work's owner, a child of the work task, in passing, `after` the work task so it starts once the work is held only on its merge, and in the report's turn when that turn is on the work task, else the work task's newest turn. The answer's second line is `Gathr gave #<n> to <reviewer> to review #<pr>.` Once per PR: none is given when a review in the chat that isn't cancelled names the PR, or has no PR and is the work's child or comes after it. A left or blocked report gives none, nor does a task given with its PR. Each report that first names a PR writes `gathr.review.give` with `gathr.review.outcome` (`given`, `not_done`, `no_reviewer`, `own_review`, `covered`, `refused: <why>`), `gathr.review.pr` and, when there is one, `gathr.task.review`. To try it: as in `tests/coordination.rs`, give a task, let its turn end, and read the task.

Each project has `<agent folder>/<Project>/Shared` and `<Project>/<Agent>`, names made safe for both disks, unique, and kept across a rename (`folder_name`); a chat with no project uses `Chats`. - What a chat waits on ([0050](decisions/0050-what-a-chat-waits-on.md)): `GET /api/chats/<id>/waiting` answers `lines`, `agents`, `gathr`, `in_words` (the same as text), `at_us` (the service's clock) and `from` (`service`). Each line has `kind` (`turn`, `queued`, `sign_in`, `approval`, `question`, `plan`, `wait`, `command`, `pr`, `given`, `merge`, `after`, `idle`, `trouble`, `update`, `stopped`), `what` (the line in words), `on` (what is waited for, in a few words), `agent`, `task`, `since_us`, `moves` (`itself`, `you`, `nobody`, or `others` for a line that follows other lines), `from` (`saved`, or `service` for what only the running service knows) and, for a wait or a PR to land, `seen`, `looked_us` and `error`; `silent_us` is null except on a running turn that is silent, where it is when the turn last made progress. They come sorted: what waits on you, then what nobody is on, then what moves by itself, the longest wait first in each. A queued turn says why it hasn't started: a pause (`you`), an update, usage, a missing engine (as saved on the turn), or what its agent's queue says: "behind this agent's turn on #3", "…in another chat", "its engine is closing", "its engine hasn't yet read a message sent into its last turn", "it compacts the conversation once this agent's background commands end"; with nothing said, "unknown". A turn behind one that waits for a sign-in, in this chat or another, waits on `you` too, and behind a queued turn held on usage or a missing engine it says "behind this agent's queued turn". A running turn is `itself` until it has made no progress for 10 minutes (20 during a tool): then it is `nobody`'s, with `silent_us`, and in words ", silent for 12 min" ([0052](decisions/0052-a-quiet-chat-is-noticed.md)); it is `itself` again once it makes progress. A wait is `nobody`'s once three looks in a row failed, and `you` under a pause. A task whose owner is paused, by the agent's pause, the chat's or the app's, is `you` too, ", paused". A task no turn is on says what it waits for (`after`, `given`, `merge`), that nothing is on it (`idle`: ready or working with no turn), or that it is blocked, failed or stopped and whether its giver was told (`trouble`). A PR to land says what Gathr's last look saw (`landings.saw`), `nobody`'s once it is left to its reviewer. Each agent in `agents` has `agent`, `name`, `state`, the one its face shows, the most pressing that holds ([0071](decisions/0071-an-agents-state-is-one-mark.md)): `needs_you` (an approval, a question of its, or its plan waits on the person), `cant_run` (it waits for a sign-in, or its last turn in the chat failed and nothing was queued after it), `working`, `stopped` (the person stopped the chat, a pause holds it, a restart cut its last turn, or the person stopped that turn), `blocked` (a task of its is blocked), `waiting` or `free`; `words` ("Waiting for CI on #157 and Ann", "Held", "Paused", "Stopped", "Usage limit", "Signed out", "Its last turn failed", "#24 is blocked", "Free"), `what` (a word or two for the face's card: "Approval", "Question", "Plan", "Signed out", "Failed", "Gathr restarted", "Paused", "Claude Code download" for a turn held for its engine's download, whom it waits for), `task` (its running turn's, its blocked task, or the turn that failed or stopped), `since_us` (since when it has been in that state: for one free, its last turn's end or when it joined), `on` (whom and what it waits for, each with `since_us`), `until_us` and `failing` (waiting, the looks at one of its waits failed three times in a row: the window's "Can't read"). `gathr` is what Gathr itself has going that no agent is on, said as an agent's state is (the owner's pick, 2026-11-18): each has `kind` (`update`, then each `pr` it lands by itself, then each `command` an ended turn left running), `state` (`working`, or `waiting` for a PR), `what` ("Update to 0.1.240", "#18 to land", what the command runs), `name` (the agent whose turn left the command), `since_us` (none for the update) and `failing` (the looks at a PR to land failed three times in a row; kept only while the service runs, so its next look after a start finds it again). A PR left to its reviewer or the person isn't Gathr's, nor a command whose turn still runs, and with the service stopped `gathr` is empty. Live `{"type": "waiting", "chat"}` whenever the chat's answer may have changed (a task or wait, a turn queued, started, held or ended, a look that saw something new or began to fail, a background command, a look at a PR to land, its looks starting or ending to fail, an approval, a queue's reason, a pause or a resume, the person's message, a turn going silent or making progress again): a window showing the chat asks again. The `waiting` tool gives an agent the same for its own chat, in words. `gathr diag waiting --chat <id>` asks the service, and with it stopped reads the database (`from`: `database`), where a running turn reads "was running when the service stopped", nothing is `itself`, and the first line (`stopped`) says the service isn't running. The `message` tool's answer names what holds the turn it queued: "once Gathr has updated", or "when Gathr", "the chat" or the agent "is resumed" (G163). An approval's `since_us` is when its turn's approvals began waiting, not when the turn began ([0058](decisions/0058-gathr-tells-you-outside-the-window.md)). To try it: as in `tests/waiting.rs` and `tests/messages.rs`.
- A quiet chat ([0052](decisions/0052-a-quiet-chat-is-noticed.md)): a chat is stuck when it has an agent's task that is neither done nor cancelled, it isn't archived, and no line of the answer above is `itself` or `you`. Gathr checks a chat after every write that changes its turns, tasks or waits (a pause, a resume and the person's message too), and at every look, each chat with such a task or an open stretch. A stretch runs from the first check that finds the chat stuck to the first that doesn't, or to the person's message in it. A count, the stuck time that leads to a telling, starts at the person's message in the chat, and when a stretch they were told in ends. Only what is new is said again. Each line has a key, its `kind`, `task`, `on`, `agent` and `since_us` and never its words: the same from check to check and when a task's giver hears of its trouble, and new for a task that is restarted and fails again. First the Supervisor is woken: a turn on no task, queued as any turn (a pause holds it), whose message with role `gathr` reads "Not moving for 6 min: #4 (Cass) and 1 more. Nothing waits on the person.", then the lines, what is new to it first, then what it can do (`gathr.quiet.woke`, with `gen_ai.agent.id` and `turn`). It goes only with news whose key wasn't in its last wake. News is a `nobody` line that is neither trouble its giver heard nor another agent's silent turn, or trouble its giver hasn't heard with no hear-back queued. It never goes while its last wake is still queued or running, or while the Supervisor's own turn is silent, and not in a chat with no Supervisor. Then, at 5 minutes of stuck time in the count, the person is told, when a line that isn't moving has a key that wasn't in the last telling: a message with role `gathr` and no turn, "Not moving for 6 min: #4 (Cass) and 1 more. Write here to move it on.", then the `nobody` lines, or every line when none is `nobody`'s, what is new first (`gathr.quiet.told`, with `stuck_us`), and the chat's `needs` is true until that stretch ends ([api.md](api.md)). Stuck time is added at each check, for the time since the check before: a gap over two looks adds nothing (the service was down, the computer asleep), none is added while the Supervisor's wake runs and makes progress, none to the count once the person is told, and none to it while every line that isn't moving was in the last telling, so a new one gets its own 5 minutes from the check that first sees it. A stretch that ends is `gathr.quiet.stretch`: `duration_us` is the stuck time counted in it, with `since_us`, `ended_by` (`moved`, or `wrote` for the person's message), `woke`, `told` and `what`, the list of what wasn't moving at its last check. One row for the chat in the `quiet` table outlasts a restart: `since_ts` (the open stretch began; null with none open), `stretch_us`, `counted_ts` (counted up to; null while the clock is stopped), `what`, `total_us` (the count's stuck time; null while nothing that isn't moving is new to the person), `wake_turn` (the Supervisor's wake in this count), `told_ts`, `reset_ts` (the person's message the count runs from), and `told_what` and `woke_what`, JSON lists of keys (`[kind, task, on, agent, since_us]`): what wasn't moving at the last telling, and the Supervisor's news at its last wake. A new count keeps both lists. A check that fails is `gathr.quiet.check` (error `sqlite`, with `why`) on the chat, and on no chat when a look can't list the chats to check. A silent turn's lead is told once for that turn, in a turn of its own: "Cass's turn on #4 has made no progress for 12 min. It is still running. A message to them reaches that turn." (`gathr.turn.silent_told`, with `gen_ai.agent.id`, `lead` and `quiet_ms`, on the silent turn's reference, beside `gathr.turn.stalled` in `gathr diag trace <ref>`; a telling that can't be saved is the same event with error `sqlite` and `why`); a Supervisor's own silent turn, and one in a chat with no Supervisor, tells nobody. `GATHR_QUIET_TELL_MS` in the service's environment shortens the 5 minutes, in dev and tests only. Dead time is read with `gathr diag query "SELECT time, conversation_id, duration_us, attrs FROM event_log WHERE name = 'gathr.quiet.stretch'"`, and a stretch still open with `gathr diag query "SELECT * FROM quiet WHERE since_ts IS NOT NULL"`. To try it: as in `tests/quiet.rs` (the rule, with the time passed in) and `tests/quiet_room.rs` (through the service, with a task left ready and no turn on it).
