# The API: pauses, archive and the agent folder

Part of [AGENTS.md](../AGENTS.md)'s Run, use and check it; the other parts are listed there. The API's address and sign-in are in [api.md](api.md).

- Pause and stop (F10, [0010](archive/decisions/0010-coordination-as-state.md)): `GET /api/pauses` lists each pause (`scope` `app`, `chat` or `agent`, its `target` id, `since_us`, `state` `pausing` while a turn or background command in it still runs, then `paused`, or `stopped` after Stop now, and what still `running`) and each account's usage hold (`until_us`, `kind`, its `agents`). `POST /api/pauses {"scope", "target"}` pauses; `POST /api/pauses/resume` resumes, which is Restart after a stop; `POST /api/pauses/stop` is Stop now: it interrupts the scope's turns, ends their engines' background commands with Claude Code's own `stop_task`, and queues a carry-on per agent that waits for Restart. A pause holds the turns Gathr queues (checks, last words, carry-ons), never the person's own message; a held turn stays `queued` with `held` (`pause` or `usage`) and its `why`, and all of it outlasts a restart. `GET /api/chats/<id>` adds `run` (the chat's own pause or the app's, else `{"state": "running"}`) and, on each member, `paused` and `usage_until_us`. A `rate_limit_event` with status `rejected` holds the account until 30 s after its reset: a turn that ran no tool is sent again then, one that did ends and a carry-on waits (`tests/frames/usage_limit.jsonl` is made by hand: no limit was hit live). When a background command ends, Claude Code starts a turn by itself: it gets its row, answering the turn that started the command. When one ends while its engine runs another turn, Claude Code says so inside that turn and begins none of its own. An engine that exits takes its commands with it. A turn with no progress for 10 minutes (20 during a tool) is silent: flagged once (`gathr.turn.stalled`), never stopped. A turn that waits for an approval isn't flagged, and answering the approval counts as progress. `GATHR_STALL_AFTER_MS` shortens the 10 minutes, in dev and tests only. Events are `gathr.pause.*` and `gathr.usage.hold`.
- Archive and delete (F11, [0010](archive/decisions/0010-coordination-as-state.md)): `POST /api/chats/<id>/archive` ends the chat's work in one step (queued turns stopped, its pause gone, one `gathr.chat.archive` event), then interrupts its running turns and ends their background commands; it answers `{"archived", "ended": {"turns"}}`. A send in an archived chat is refused (409, `the chat is archived`). A turn archiving stopped stays stopped: a start under way then (its engine's version or login being read) drops it rather than leave it waiting for a sign-in, and an ended turn never goes back to `queued` or `waiting_sign_in`. `POST …/unarchive` puts it back in the list and starts nothing. `DELETE /api/chats/<id>` archives it first, closes its engines the gentle way, removes its rows, then its worktrees (their branches stay) and hooks: `{"deleted", "left"}`, `left` naming what couldn't be removed, with its reference. Archiving also removes the chat's worktrees in the agent folder (below), which a restored chat's next turn checks out again from their branches, but keeps a worktree with changes not committed, and a chat's folder outside a project, until the chat is deleted. Each sends `{"type": "chat", "chat", "change"}` live (`archived`, `unarchived`, `deleted`).
- The agent folder ([0034](archive/decisions/0034-agent-folder.md)): `GET /api/settings` answers `agent_folder`, a full path (unset, the home folder's `Gathr` for the system's own data folder, else `<data>-agents` beside the data folder, so a test folder, opened by `cargo dev` or by `gathr-app --data`, keeps its agents to itself); `PATCH /api/settings {"agent_folder"}` saves it, or refuses (400, with a reference) a path that isn't full, holds or is in the data folder, or can't be made or written. It applies to new work. Each project has `<agent folder>/<Project>/Shared` and `<Project>/<Agent>`, names made safe for both disks, unique, and kept across a rename (`folder_name`); a chat with no project uses `Chats`. An agent's worktree is `<Agent>/<chat>` (the chat id's last six characters), a plain chat's folder the same, and each engine's `TEMP`, `TMP` and `TMPDIR` is `<Agent>/temp/chat-<chat>`, fixed when it starts and cleared once it closes (never a restart to change it). Claude Code gets `--add-dir` for the agent's folder and Shared, Codex both as writable roots; one that holds the data folder or leads into it through a link isn't passed (`gathr.folder.refused`, with a reference), an agent folder that does (a link made after it was saved) fails the turn before anything is made, and the hook asks before any write that lands in the data folder, links followed, except in an engine's own folder from before the agent folder (`<data>/worktrees/<chat>/<agent>`, `<data>/chats/<chat>`) while no link in it leads elsewhere (one that does fails the turn the same way). Paths are as the disk names them (macOS's `/private/var`), so a test compares the engine's folders with `gathr::folders::real`. Every folder is recorded before it's made (`agent_folders`; the start event's `gathr.folder.*`); worktrees from before stay in `<data>/worktrees` for an agent with a session there. A sweep every two minutes (and at once on archive and delete) removes a closed engine's temp folder, an archived chat's worktrees, a deleted chat's folders and a deleted project's own folders (recorded with no chat: each agent's folder, `checks`, `caches`; never `Shared`, [0069](archive/decisions/0069-deleting-a-project-or-an-agent.md)), never one a running engine uses, nor one whose chat was restored meanwhile: `gathr.cleanup.skip` (`in_use`, `changes`, `in_data`, `left`) with a reference, then `gathr.cleanup.remove` on the same trace. To try it: `cargo dev`, a project chat, a message; the start event's `cwd` is under `<data>-agents`; archive the chat and look for `gathr.cleanup.*` in `gathr diag failures` and `diag trace`.
