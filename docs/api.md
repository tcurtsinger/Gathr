# The API

Part of [AGENTS.md](../AGENTS.md)'s Reference; the other parts are listed there.

- **The API** is on `127.0.0.1:<port>`. Every `/api` request needs `Authorization: Bearer <token>`, with the token from `<data>/service.json`, or the browser's cookie `gathr-<port>`: `POST /api/once` gives a code, and opening `/?once=<code>` swaps it for the cookie (HTTP-only, `SameSite=Strict`, new at each start of the service but one that takes over from a hand-over to an update, which keeps the token and the cookie). Other paths serve the built UI, but `/view/` below. A Host other than `127.0.0.1:<port>` or `localhost:<port>`, or an Origin other than those or the window's (`http://tauri.localhost`, `tauri://localhost`), is refused (403) before the token is looked at. Errors answer `{"error": "… failed", "why", "ref"}`, and each is recorded before the answer goes out, so its `ref` traces at once; every answer carries its reference in `x-gathr-ref`. `GET /health` (token too) answers `{"status", "version", "build", "pid", "port", "data_folder", "database_bytes", "schema_version", "started"}`; `POST /api/shutdown` stops the service (202, `{"stopping": true}`).
  - Chats: `GET`/`POST /api/chats` (`?archived=true` lists the archived ones instead, each with `archived`; every other row carries `working`, a turn of it is running, `queued`, a turn of it waits to start by itself (behind its agent's other work, an engine download or an update; not one held for usage or by a pause), and `needs`, it waits on the person: through an approval, a question to them or a message held for a sign-in, and `mark`, what its row shows: `needs_you` for all of those but a sign-in, else `cant_run` while an agent of it waits for a sign-in or its last turn failed, else `working`, else null, [0040](archive/decisions/0040-chat-state-in-the-list.md), [0071](archive/decisions/0071-an-agents-state-is-one-mark.md)), `GET /api/chats/<id>` (messages in their turns' order, each with its `agent`; turns, each with the turn it `answers` (a check's, the lead's answer it checks), its `opened` (what opened it, [0056](archive/decisions/0056-gathr-records-which-words-opened-each-turn.md): `person`, `teammate`, `picked` (Gathr's copy for a picked agent, or a question's answer), `reply`, `check` for a member's check of the lead's answer and `last_word` for the lead's last word ([0080](archive/decisions/0080-the-team-checks-the-leads-answer-in-the-open.md)), `carry_on`, `compaction`, `engine` (a turn the engine began when a background command ended), `scheduled` (a scheduled run), `brief` (a proposed project's brief), `app` (words an AI app outside Gathr sent), these three below, or `nudge` (Gathr handed an agent its turn back once because its board line still said doing when the chat went quiet, [api-tasks.md](api-tasks.md)); on the live `turn` event too), its `ended` (when it ended, null until then; on the live `turn` event too, so the name line says how long it took, [0082](archive/decisions/0082-a-message-reads-as-serenityos-card.md)), and for a stopped one `end`, who or what stopped it in a word: `you` (the person's Stop or Stop now), `restart` (a restart cut it: never `failed`), or Gathr's own, `usage` or `gathr`; null otherwise, read from its status and `why`, and sent on the live `turn` event too; `project` and `folder`; `members` (every chat that has an agent keeps its list, a chat of one its agent as `supervisor`, [0028](archive/decisions/0028-team-chats.md); none before its first message to an agent); open `approvals`; `streaming`, each agent's reply text not saved yet; `reactions`, each agent's thumbs-up on a message and the person's likes (`agent` `person`), oldest first: `{"message", "agent", "time"}`, `message` the id of an agent's message or, for an agent's thumbs-up, of the person's, never Gathr's copy of it, [0057](archive/decisions/0057-agreeing-is-a-reaction.md)); `reads`, where the person left off, by thread ([0077](archive/decisions/0077-where-you-left-off.md)): `{"topic", "seen_us", "folded"}`, `topic` the thread's key as `topic` names it (`''` for the main line), `seen_us` when the newest message seen there was said, `folded` the person's own fold (`true`), open (`false`) or `null`; none for a chat not opened since 0077, `POST /api/chats/<id>/messages {"text", "agent", "picks"}` (as that agent; with none, on the oldest account; `picks`, optional, the names the person picked from the `@` list (a name typed whole counts too), each of whose agents gets it too, below). An agent runs one turn at a time across its chats, with its own engine session in each chat, so a message for a busy agent answers `queued`. `POST /api/chats/<id>/stop` (the chat's turns, whichever agent they're for; `{"stopped"}`), `POST /api/chats/<id>/approvals/<request_id> {"allow"}` (`{"answered": true}`, else 404 "Answer failed"). Where the person left off ([0077](archive/decisions/0077-where-you-left-off.md)): `PUT /api/chats/<id>/reads {"reads": [{"topic", "seen_us"?, "folded"?}]}` keeps each thread's mark and fold, all or none, and answers `{"reads"}`, each row as kept; a mark never moves back, a fold is the latest, and a `topic` that isn't a thread of this chat refuses the lot, `409` "Marks failed" with why and a reference. The window writes at most once a second. The person's like ([0057](archive/decisions/0057-agreeing-is-a-reaction.md) C4): `PUT /api/chats/<id>/messages/<message>/like` gives it, `DELETE` the same takes it back (`{"removed", "message"}`, `removed` false and `message` null when none stood: no error). The give answers `{"reaction", "did"}`: `marked` (the mark alone: it starts no turn and Gathr writes the agent nothing) or `standing` (one already stands: nothing more). Refused (409, with why and a reference): a message not in the chat, the person's own, Gathr's line, a step, an archived chat.
  - A tool call is a message of `kind` `tool` whose `body` is `{"tool", "status", "duration_ms", "input"}`: `running` at its start (a live `message`), then `ok`, `error` or `stopped` with `duration_ms` (a live `{"type": "tool", "message", "body"}`, the body as history then has it). `input` is what it ran ([0041](archive/decisions/0041-what-a-step-ran.md)): `{"text", "title"}`, `text` a command's first line (Codex's out of the shell it wraps it in), a file's path or a search's words, one line of at most 200 characters ending "…" where more followed, with secrets hidden as in Diagnostics (`[redacted:<kind>]`); `title` the engine's own words for the call, when it gives some. Kept for Claude Code's `Bash`, `PowerShell`, `Read`, `Write`, `Edit`, `Grep`, `WebFetch` and `Agent`, and Codex's commands (`Shell`), file changes (`Edit`) and web searches (`WebSearch`, whose words come only with its end). Gathr's own tools, other MCP tools and anything else have no `input`, as messages from before it have none. The text is in the message only, never in an event, so a bundle holds none of it; a sub-agent's own tools are not kept or shown. A listed tool whose frame lacks its field (a sub-agent's too) keeps nothing and records `gathr.engine.tool_input` (error `shape_changed`, `gen_ai.tool.name`, `field`) on the turn's reference. To see it without a login, replay `steps_claude` or `steps_codex` (hand-written frames, [running.md](running.md)); `steps_shape_changed` forces the failure. A command's `input` also has `request`, the whole command up to 8 lines and 2,000 characters, hidden first, when that's more than its one line ([0044](archive/decisions/0044-what-a-step-returned.md)). An ended step has `result` (0044): `{"text", "lines", "more"}`, up to 5 lines, each hidden then cut to 200 characters: a command's last lines (and `exit N` when Codex says it failed), a read's line count only, an edit's lines added and removed, a search's count and first hits, and the first lines of anything else (Gathr's tools, a sub-agent's report, an error). Live turns to replay: `results_claude`, `results_codex`. A step that changed files has `changed`: `[{"path", "full", "added", "removed"}]`, one per file, as the engine reported them (Claude Code's patch of a `Write` or `Edit`, each line of a new file added; each file of a Codex file change, a new file's every line added); `path` is from the folder the engine runs in when the file is there, `full` the whole path when that's another. When the engine's report is text, the stored step also keeps the change itself for the Changes tab: `diff`, unified diff hunks (a new file one hunk, every line added), secrets hidden, at most 2,000 lines and 2 MB with `cut` true past that, and `new` when the step made the file. The lines are never sent to the window with a chat's messages or its live `tool` event, nor are in an event, a log, search or `read_chat`: only the Changes routes give them. A failed or refused call, a sub-agent's, a file a command changed and messages from before have none of it. The window sums a turn's into the card under its words.
  - That the agent thought is a message of `kind` `thinking` ([0042](archive/decisions/0042-thinking.md)), role `assistant`, whose `body` is `{"status", "duration_ms", "tokens"}`: never any text. `tokens` is the engine's own estimate, when it gives one. Both engines: `{"status": "running"}` when the thought starts (a live `message`), then `done`, or `stopped` when the turn was cut off, with `duration_ms` (the same live `{"type": "tool", "message", "body"}` a tool's end sends). Gathr asks Codex for a reasoning summary so that it says when a thought starts; the summary's text is never kept in a message, an event or this API (the raw frame record holds it, as it holds a reply's text: `gathr diag turn --raw`). A Codex thought opens a quarter of a second after it starts, with its `time` and `duration_ms` counted from the start. When Codex says a thought started and ended at once (a model that gives no summary), it is a mark of one already over: the message arrives whole, `done`, as one live `message`, its `duration_ms` the quiet before the mark and its `time` when that quiet began; a mark under a second after the turn last showed progress, or while a step runs, makes none. A turn the service died in is failed at the next start, and its `tool` and `thinking` messages still `running` become `stopped`, such a thought with no `duration_ms`. A `thinking` message is never searched, never in `read_chat`, and a turn with nothing else is done: it had nothing to add. Each one kept records `gathr.turn.thinking` on the turn's reference (its duration, `gathr.thinking.tokens_estimate`; error `stopped` for one cut off). To see it without a login, replay `thinking_claude`, `thinking_codex_live` or `thinking_codex` (marks); `thinking_cut_off` forces the failure.
  - A table, a chart, a flow, math steps, a diagram or a page an agent showed with the tool `show` is a message of `kind` `block` (migration 0078), role `assistant`, in the caller's turn, sent live as a `message`; its `body` is `{"kind": "table" | "chart" | "flow" | "math" | "diagram" | "page", "title"?, <the kind's field>}`, as the tool took it, with only its kind's field. `table` is `{"columns": [{"key", "label", "as"?, "unit"?, "currency"?, "decimals"?, "up_is_good"?}], "rows"}` (`as`: `text`, `number`, `money`, `percent`, `change`, `date`, `link` or `yes_no`; 1 to 12 columns, at most 200 rows, each value a string of at most 500 characters, a number, a boolean or null, as its column's `as` wants; a `link` is an http(s) address or `[name](address)` with one); `chart` is `{"label", "value", "points", "labels"?, "change"?, "vs"?, "style"?, "up_is_good"?}` (2 to 500 points; `labels` a name for each point, as many as the points, each at most 12 characters; `vs` what `change` is measured against, at most 16 characters; `style` `line`, `area` or `bars`); `flow` is `{"nodes": [{"id", "label", "after"?, "state"?}]}` (2 to 40 nodes, ids unique, `after` the ids it follows, no loop; `state` `done`, `active` or `pending`, the default); `math` is `{"label"?, "steps": [{"expression", "note"?}]}` (1 to 30 steps; an expression is plain text of at most 200 characters, its note at most 120); `diagram` is `{"mermaid"}` (1 to 20,000 characters, not parsed by the service) or `{"file"}` (the full path of a png, jpg, jpeg, gif, webp or svg); `page` is `{"file", "height"?}` (the full path of an .html or .htm file; `height` 160 to 720, 360 unless set). A `diagram` or `page` file must be a file in the chat's tree, as a file tab reads it, or it is refused. A call over 100 KB, or one that doesn't fit, is refused with what is wrong and nothing is kept; a good one answers `Shown.`. A block is never searched and never heard by a teammate's turn; `read_chat` gives it as one line, `[table: <title>, 12 rows]`, `[chart: <title or label>, 30 points]`, `[flow: <title>, 7 steps]` or `[math: <title or label>, 4 steps]`, `[diagram: <title>]` or `[page: <title or file name>]`. A project the assistant proposed with `propose_project` is a block too, of kind `project`, and an agent it proposed with `propose_agent`, of kind `agent` (the assistant's own chat, below).
  - Team chats ([0028](archive/decisions/0028-team-chats.md)): `POST /api/chats {"members": [{"agent", "role"}]}` (`supervisor`, the lead, or `member`) or `{"project"}` (copies the project's folder and team), `PATCH /api/chats/<id> {"members"}` replaces the whole list; `{"project"}` puts a chat with no messages yet in a project (409 once it has some). `{"title"}` renames it, an archived one too: one line of 1 to 60 characters, trimmed, else 409 "Rename failed" with why; it answers `{"chat", "title"}`, records `gathr.chat.rename` (without the name) and sends `{"type": "chat", "chat", "change": "renamed"}` live. The person's name is final: the background model never names the chat after it. A message goes to its `agent`, else the lead (or the only agent); each `@Name` in its text that names an agent the window's `@` list offers (the chat's team, and in a chat with no project every other agent), whole and ignoring case as an agent's words are read, counts as picked and is kept in `picks`, and a message sent with no picks goes to the first name it types. In a chat with no project and no agents yet, a message with no `agent` and no picks goes to the assistant. In a chat with no project, the first `agent` a message goes to becomes its lead, and an `agent` from outside joins it as a member; in a project chat it must be one of the chat's. `picks` keeps each picked name with the message so the window draws it blue (0072): `[{"at", "len", "agent"}]`, `at` where its `@Name` starts and `len` its length with the `@`, both in UTF-16 code units of `text`, as the window counts. Every picked agent gets the message ([0028](archive/decisions/0028-team-chats.md), 2026-11-18): it is saved once, in the turn of `agent`, and each other picked agent gets Gathr's copy of it (a `gathr` message with `copy_of` the person's message, never drawn) in its running turn in the chat or a turn of its own, which a pause never holds. Each engine reads one line of Gathr's before the words, naming the others: `The person sent this to you and Bo.` (kind `picked`), or for a reply the `reply` kind's line ending `They sent it to you and Bo.`. In a project chat a picked agent outside its team refuses the send (400 `a picked agent isn't in this chat`); in a chat with no project the outsiders join in one `members` change, and one too many refuses it (400 `A chat needs 1 to 5 agents`), both before anything is saved. The send's answer keeps the first agent's `turn`, `status` (and `steered`, `ref`) and adds `message`, the saved message's id, and `turns`: `[{"agent", "turn", "status"}]`, one per agent in order, `steered` on one that joined a running turn; a copy that couldn't go is `{"agent", "status": "failed", "why", "ref"}` and the others still go. `gathr.chat.send` carries `gathr.send.agents`. A pick that isn't inside the text, cuts a character in half, doesn't start with `@`, is `@` alone, overlaps another, or names an agent that isn't known is refused (400, with the reason and a reference). The person's message in history and on the live `message` carries its `picks`, in text order; every other message, a message with no pick and one saved before they were kept have `null`.
  - Room chats: every chat is a room chat. No ask, task, wait, hold or plan is kept, every turn runs in its agent's latest conversation and opens with what the room said since its last turn, a turn with nothing to add ends done, and every agent is offered only `react`, `set_board_line`, `ask_person`, `read_chat`, `note`, `show`, `schedule`, `unschedule`, `pr`, `ci_failures`, `update_pr`, `add_tool`, `add_skill`, `send_out`, `propose_project`, `propose_agent`, `propose_agent_change` and `propose_project_change`; the last five refuse any agent but the assistant in its own chat (below). Each engine is allowed all of them without asking but `add_tool` and `add_skill`, which it asks about as the agent's Approvals say: Claude Code's `--allowedTools` leaves them out, and Codex gets `mcp_servers.gathr.tools.<tool>.approval_mode="prompt"` for each (its own mode wins over the server's `approve`; Full's `never` with full access allows it). The board: `GET /api/chats/<id>/board` answers `{"lines", "agents"}`, `agents` how many the chat has and each line `{"id", "owner", "name", "text", "state"}` in the order added, `state` `to_do`, `doing`, `in_review` or `done`. Only agents set it, with `set_board_line` (`line` to change or, with `remove`, take off one; none adds one, with `text`, owned by the caller unless `owner` names an agent of the chat, at `to_do` unless `state` says), and each change sends `{"type": "board", "chat", "lines"}` live; Gathr starts nothing from it. `ask_person` keeps a question of its own (migration 0067), never a task; its `files`, full paths each in the chat's tree (below, `GET /api/chats/<id>/files`; else the tool refuses), are kept in `question` as `Attached: <full path>` lines after the words (an agent is told to ask for a design's pick with the design's pages as `files` and one choice per page, in the same order; the window reads such a question as the design's options, [window.md](window.md)): `GET /api/chats/<id>` carries `questions`, oldest first, each `{"id", "chat", "agent", "name", "question", "choices": [{"label", "detail"}], "pick", "words", "asked", "answered", "closed"}` (`answered` null while open; `closed` when archiving its chat closed it unanswered); while one is open the chat `needs` the person, with `mark` `needs_you`. `POST /api/questions/<id>/answer {"pick", "words"}` (either or both) answers `{"question", "turn"}`, the asking agent's turn that opens with the answer (`opened` `picked`); refused (409) for a question that isn't there, is answered or was closed, a pick that isn't one of its choices, or neither. Each ask and answer sends `{"type": "questions", "chat", "questions"}` live, the chat's questions whole. An agent's words that start with `REPLY` on a line of its own are saved without it, with `reply_to` the main message of the teammate's message that woke the turn (none when the person's did); history, the live `message` and each live `delta` carry `reply_to`, and `streaming` too. The lead's answer is checked (0080) from each turn's end.
  - Files in messages: `POST /api/chats/<id>/files?name=<file name>` takes a file as the raw body, at most 10 MB, and saves it in `<agent folder>/<Project>/Shared/files/<chat part>` (a chat with no project: `Chats`), under its name made safe and unique there (`shot.png`, then `shot 2.png`); it answers `{"name", "path"}`. That folder is recorded with the chat, so deleting the chat removes it. `POST /api/chats/<id>/messages` and `POST /api/questions/<id>/answer` take `"files"`, the saved names: each must be in that chat's folder (else 400), and adds a line `Attached: <full path>` after the words, which may then be empty. The engine opens the file from that path. A chat's title skips those lines. `GET /api/chats/<id>/picture?path=<full path>` answers a png, jpeg, gif or webp only when the path, links and `..` followed, is anywhere in the chat's project: its folder in the agent folder (Shared and every agent's folders), its part of Designs or the project's own folder; else 404 "Picture failed". It is sent with `X-Content-Type-Options: nosniff` and a sandbox `Content-Security-Policy`. `GET /api/chats/<id>/files` answers the chat's tree, as the window's Files tab shows it: `{"project", "shared", "designs", "agents"}`, each a folder `{"name", "path"}` (an agent's with `"agent"`, its id), only those on the disk: the project's own folder (null in a chat with no project), Shared, the project's part of Designs (`<agent folder>/Designs/<Project>`, named "Designs"; never another project's), and each agent's folder for this chat as recorded when it was made, never another chat's. With `?path=<full path>` it answers one folder inside those, `{"entries": [{"name", "path", "folder", "modified"}]}`, folders first and then files, each by name, without `.git`, `modified` when it last changed in milliseconds since 1970 (the Designs tab lists the newest design first); a path outside them, links and `..` followed, is 404 "Files failed". With `?find=<words>` it answers the files inside those folders whose name holds the words, case ignored, `{"found": [{"path", "crumbs"}]}`, `crumbs` the top folder's name, the folders down and the file's name: a name that starts with the words first, then by name, at most 50, never in `.git` or through a link out of them. In a git checkout git lists the files (tracked, and new ones not ignored), so what the project ignores is never read; any other folder is walked. `GET /api/chats/<id>/file?path=<full path>` answers a file inside the same folders as `text/plain; charset=utf-8`, with the picture's headers and `Cache-Control: no-store`: 404 "File failed" when it isn't a file there, 413 over 2 MB, 415 when it isn't UTF-8 text. `GET /api/chats/<id>/pdf?path=<full path>` answers a `.pdf` file inside the same folders as `application/pdf` with the same headers, for the window to draw with PDF.js: 404 "PDF failed" when it isn't a file there, 413 over 50 MB, 415 when it doesn't end in `.pdf`. `GET /api/chats/<id>/sheets?path=<full path>` reads an `.xlsx`, `.xlsm`, `.xls` or `.ods` workbook inside the same folders with calamine and answers its visible worksheets in order, `{"sheets": [{"name", "rows", "total"}]}`: `rows` the sheet's first 2,001 rows (a heading row and the 2,000 a table draws) from its first cell that holds something, each cell as text as the person reads it (a whole number without `.0`, a number to 15 significant digits, a date `2026-05-02`, a time `14:30`, both `2026-05-02 14:30`, a duration `36:15:00`, `TRUE`, an error such as `#DIV/0!`, an empty cell `""`; the cell's own number format isn't read, so `84.00` reads `84`), `total` how many rows it has in all; 404 "Sheets failed" when it isn't a file there, 413 over 10 MB, 415 when it isn't one of those or calamine can't read it (damaged, or locked with a password). `POST /api/chats/<id>/view?path=<full path>` opens a view of a file inside the same folders, for an HTML page to show as it looks: it answers `{"address"}`, `http://127.0.0.1:<port>/view/<key>/<file name>`, `<key>` 64 random hex characters, or 404 "Page failed" when it isn't a file there. With `&notes=true` (a design's tab in the chat) the path must be an `.html` or `.htm` page right in a design's folder in the chat's part of Designs, else 404 "Page failed", and that page, and nothing else of the view, is served with a script added after its end: while the window says Comment is on it outlines the part under the pointer and, on a click, stops the page's own handling and posts `{"gathr": "clicked", "kind", "words", "find", "rect"}` to the window that holds the frame; it draws the pins the window posts it (`{"gathr": "notes", "on", "pins": [{"n", "settled", "kind", "words", "find"}]}`) in a layer of its own. `GET /view/<key>/<path>` needs no token or cookie, as the key is the permission, and its `Origin` isn't checked (a sealed page's own requests say `null`); its Host is. It answers a file in the page's folder or below it, never one named with a leading dot or inside such a folder (`.env`, `.git`) and only the kinds a page loads (a page, style, script, picture, font, media or data file, by its ending), links and `..` followed, with its media type by its ending, `nosniff`, `Cache-Control: no-store`, `Access-Control-Allow-Origin: *` and `Content-Security-Policy: sandbox allow-scripts; default-src http://<host>/view/<key>/ https: data: blob: 'unsafe-inline' 'unsafe-eval'`, so the page runs with no origin and loads only from its own folder under that key and from `https:`; else 404 "Page failed". Views are kept in memory only, the newest 100: a restart, or 100 newer views, lets one go. `GET /api/designs` answers every design, for the Designs screen: `{"parts": [{"folder", "project", "chat", "designs": [{"name", "path", "pages", "modified"}]}]}`, a part for each folder in `<agent folder>/Designs` that holds a design, the part with the newest design first; `project` is `{"id", "name"}` of the project with that folder name (null for `Chats`, or when no project has it), `chat` that project's newest chat that isn't archived, else null. A design is a folder in a part that holds at least one `.html` or `.htm` page, newest first; `pages` are their full paths by name, `modified` when its newest page changed, in milliseconds since 1970. A name with a leading dot, and a folder or page that, links and `..` followed, is outside Designs, are never listed. `POST /api/designs/view?path=<full path>` opens a view of a page inside Designs as a chat's view does, with no chat, else 404 "Page failed". These views are kept apart from the chats', the newest 100 of them, and a design's folder keeps one key while it is kept: the screen's many cards never let a chat's view go.
  - Changes (the Changes tab): `GET /api/chats/<id>/changes` answers `{"agents", "more"}`: each agent of the chat that has a worktree in it (Gathr's own for that agent and chat) or wrote in a checkout elsewhere, as `{"id", "name", "branch", "files", "outside"}` (`branch` null without a worktree), each file `{"path", "from", "added", "removed", "kind", "binary"}`, by path: `path` from the worktree with `/` between steps, `kind` `changed`, `new`, `deleted` or `renamed` (with `from`, its old path), a binary file with no counts. A change is everything in the worktree not yet on the project's main line: its working tree against the merge-base of its HEAD with the project's `origin/HEAD` (with no origin, the project's own HEAD), read with `git diff-index`, which never writes the index, and its new files git doesn't ignore (`ls-files --others --exclude-standard`), each counted from the disk. `outside` is `[{"folder", "files"}]`, one per other git checkout the agent wrote in with its file tools, in a chat with a project or without: the files its steps wrote there (Claude Code's `Write` and `Edit` by their path, Codex's file change by the first file it names), as that checkout's working tree against its HEAD and its new files git doesn't ignore, by path from `folder`, the checkout's top (the nearest folder at or above the file holding `.git`, as the disk names it). A file the agent wrote that is now committed or as it was shows nothing; the checkout's other files, the person's, never show.
