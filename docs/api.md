# The API

Part of [AGENTS.md](../AGENTS.md)'s Run, use and check it; the other parts are listed there.

- **The API** is on `127.0.0.1:<port>`. Every `/api` request needs `Authorization: Bearer <token>`, with the token from `<data>/service.json`, or the browser's cookie `gathr-<port>`: `POST /api/once` gives a code, and opening `/?once=<code>` swaps it for the cookie (HTTP-only, `SameSite=Strict`, new at each start of the service). Other paths serve the built UI. Errors answer `{"error": "… failed", "why", "ref"}`, and each is recorded before the answer goes out, so its `ref` traces at once.
  - Chats: `GET`/`POST /api/chats` (`?archived=true` lists the archived ones instead, each with `archived`; every other row carries `working`, a turn of it is running, and `needs`, it waits on the person: through an approval, a question to them, a plan that has reached them or a message held for a sign-in, or because Gathr told them it isn't moving, until that stretch ends, and `mark`, what its row shows: `needs_you` for all of those but a sign-in, else `cant_run` while an agent of it waits for a sign-in or its last turn failed, else `working`, else null, [0040](decisions/0040-chat-state-in-the-list.md), [0052](decisions/0052-a-quiet-chat-is-noticed.md), [0071](decisions/0071-an-agents-state-is-one-mark.md)), `GET /api/chats/<id>` (messages in their turns' order, each with its `agent`; turns, each with its `task`, the turn it `answers`, its `topic` (the main message it sits under, [0075](decisions/0075-a-team-chat-is-main-messages-each-with-its-thread.md): `t:<task>` a task or question, `m:<message>` the person's message or a main line of Gathr's, `r:<turn>` an ask's result, `b:<turn>` a turn's bubble as a main message of its own, said to the person or tied to nothing ([0078](decisions/0078-said-to-you-is-main-one-bubble-per-turn.md)); on the live `turn` event too, and on each line said in no turn, its message's `topic`, in history and as the line goes out live; `gathr diag threads --chat <id>` says why each), its `result_of` (the ask whose result it is, on the live `turn` event too), and for a stopped one `end`, who or what stopped it in a word: `you` (the person's Stop or Stop now), `restart` (a restart cut it: never `failed`), or Gathr's own, `plan` (its task waits for its plan), `cancelled` (its task was cancelled), `usage` or `gathr`; null otherwise, read from its status and `why`, and sent on the live `turn` event too ([0051](decisions/0051-the-giver-hears-when-all-is-in.md)); `project` and `folder`; `members` (every chat that has an agent keeps its list, a chat of one its agent as `supervisor`, [0028](decisions/0028-team-chats.md); none before its first message to an agent); open `approvals`; `streaming`, each agent's reply text not saved yet; `reactions`, each agent's thumbs-up on a message and the person's likes (`agent` `person`), oldest first: `{"message", "agent", "time"}`, `message` the id of an agent's message or, for an agent's thumbs-up, of the person's, never Gathr's copy of it, [0057](decisions/0057-agreeing-is-a-reaction.md)); `reads`, where the person left off, by thread ([0077](decisions/0077-where-you-left-off.md)): `{"topic", "seen_us", "folded"}`, `topic` the thread's key as `topic` names it (`''` for the main line), `seen_us` when the newest message seen there was said, `folded` the person's own fold (`true`), open (`false`) or `null`; none for a chat not opened since 0077, `POST /api/chats/<id>/messages {"text", "agent", "picks"}` (as that agent; with none, on the oldest account; `picks`, optional, the names the person picked from the `@` list, each of whose agents gets it too, below). An agent runs one turn at a time across its chats, with its own engine session in each chat, so a message for a busy agent answers `queued`. `POST /api/chats/<id>/stop` (the chat's turns, whichever agent they're for), `POST /api/chats/<id>/approvals/<request_id> {"allow"}`. Where the person left off ([0077](decisions/0077-where-you-left-off.md)): `PUT /api/chats/<id>/reads {"reads": [{"topic", "seen_us"?, "folded"?}]}` keeps each thread's mark and fold, all or none, and answers `{"reads"}`, each row as kept; a mark never moves back, a fold is the latest, and a `topic` that isn't a thread of this chat refuses the lot, `409` "Marks failed" with why and a reference. The window writes at most once a second. The person's like ([0057](decisions/0057-agreeing-is-a-reaction.md) C4): `PUT /api/chats/<id>/messages/<message>/like {"questions"}` gives it, `DELETE` the same takes it back (`{"removed"}`, false when none stood: no error). The give answers `{"reaction", "did"}`: `delivered` (with `turn`, the agent's turn it started or joined, as a send answers it: `status`, and `steered` when it joined a running one), `answered` (`questions`, the waiting questions the message's bubble holds, each answered with its asker's pick, as a pick does), `approved` (the message is a plan version waiting for the person: Approve), `marked` (the mark alone: given before, or the agent was removed or left the chat's team) or `standing` (one already stands: nothing more). Refused (409, with why and a reference): a message not in the chat, the person's own, Gathr's line, a step without `questions`, a question not asked in that message, already answered or with no pick, a superseded or decided version, an archived chat.
  - A tool call is a message of `kind` `tool` whose `body` is `{"tool", "status", "duration_ms", "input"}`: `running` at its start (a live `message`), then `ok`, `error` or `stopped` with `duration_ms` (a live `{"type": "tool", "message", "body"}`, the body as history then has it). `input` is what it ran ([0041](decisions/0041-what-a-step-ran.md)): `{"text", "title"}`, `text` a command's first line (Codex's out of the shell it wraps it in), a file's path or a search's words, one line of at most 200 characters ending "…" where more followed, with secrets hidden as in Diagnostics (`[redacted:<kind>]`); `title` the engine's own words for the call, when it gives some. Kept for Claude Code's `Bash`, `PowerShell`, `Read`, `Write`, `Edit`, `Grep`, `WebFetch` and `Agent`, and Codex's commands (`Shell`), file changes (`Edit`) and web searches (`WebSearch`, whose words come only with its end). Gathr's own tools, other MCP tools and anything else have no `input`, as messages from before it have none. The text is in the message only, never in an event, so a bundle holds none of it; a sub-agent's own tools are not kept or shown. A listed tool whose frame lacks its field (a sub-agent's too) keeps nothing and records `gathr.engine.tool_input` (error `shape_changed`, `gen_ai.tool.name`, `field`) on the turn's reference. To see it without a login, replay `steps_claude` or `steps_codex` (hand-written frames, [running.md](running.md)); `steps_shape_changed` forces the failure. A command's `input` also has `request`, the whole command up to 8 lines and 2,000 characters, hidden first, when that's more than its one line ([0044](decisions/0044-what-a-step-returned.md)). An ended step has `result` (0044): `{"text", "lines", "more"}`, up to 5 lines, each hidden then cut to 200 characters: a command's last lines (and `exit N` when Codex says it failed), a read's line count only, an edit's lines added and removed, a search's count and first hits, and the first lines of anything else (Gathr's tools, a sub-agent's report, an error). Live turns to replay: `results_claude`, `results_codex`.
  - That the agent thought is a message of `kind` `thinking` ([0042](decisions/0042-thinking.md)), role `assistant`, whose `body` is `{"status", "duration_ms", "tokens"}`: never any text. `tokens` is the engine's own estimate, when it gives one. Both engines: `{"status": "running"}` when the thought starts (a live `message`), then `done`, or `stopped` when the turn was cut off, with `duration_ms` (the same live `{"type": "tool", "message", "body"}` a tool's end sends). Gathr asks Codex for a reasoning summary so that it says when a thought starts; the summary's text is never kept in a message, an event or this API (the raw frame record holds it, as it holds a reply's text: `gathr diag turn --raw`). A Codex thought opens a quarter of a second after it starts, with its `time` and `duration_ms` counted from the start. When Codex says a thought started and ended at once (a model that gives no summary), it is a mark of one already over: the message arrives whole, `done`, as one live `message`, its `duration_ms` the quiet before the mark and its `time` when that quiet began; a mark under a second after the turn last showed progress, or while a step runs, makes none. A turn the service died in is failed at the next start, and its `tool` and `thinking` messages still `running` become `stopped`, such a thought with no `duration_ms`. A `thinking` message is never searched, never in `read_chat`, and a turn with nothing else still fails as empty. Each one kept records `gathr.turn.thinking` on the turn's reference (its duration, `gathr.thinking.tokens_estimate`; error `stopped` for one cut off). To see it without a login, replay `thinking_claude`, `thinking_codex_live` or `thinking_codex` (marks); `thinking_cut_off` forces the failure.
  - Team chats ([0028](decisions/0028-team-chats.md)): `POST /api/chats {"members": [{"agent", "role"}]}` (`supervisor`, `reviewer`, `member`) or `{"project"}` (copies the project's folder and team), `PATCH /api/chats/<id> {"members"}` replaces the whole list; `{"project"}` puts a chat with no messages yet in a project (409 once it has some). A message goes to its `agent`, else the Supervisor (or the only agent); its text is never read for names, as the window sends the agent picked from its `@` list (C24). In a chat with no project, the first `agent` a message goes to becomes its Supervisor, and an `agent` from outside joins it as a member; in a project chat it must be one of the chat's. `picks` keeps each picked name with the message so the window draws it blue (0072): `[{"at", "len", "agent"}]`, `at` where its `@Name` starts and `len` its length with the `@`, both in UTF-16 code units of `text`, as the window counts. Every picked agent gets the message ([0028](decisions/0028-team-chats.md), 2026-11-18): it is saved once, in the turn of `agent`, and each other picked agent gets Gathr's copy of it (a `gathr` message with `copy_of` the person's message, never drawn) in its running turn in the chat or a turn of its own, which a pause never holds. Each engine reads one line of Gathr's before the words, naming the others: `The person sent this to you and Bo.` (kind `picked`), or for a reply the `reply` kind's line ending `They sent it to you and Bo.`. Every answer's turn has the message's `topic`. In a project chat a picked agent outside its team refuses the send (400 `a picked agent isn't in this chat`); in a chat with no project the outsiders join in one `members` change, and one too many refuses it (400 `A chat needs 1 to 5 agents`), both before anything is saved. The send's answer keeps the first agent's `turn`, `status` (and `steered`, `ref`) and adds `message`, the saved message's id, and `turns`: `[{"agent", "turn", "status"}]`, one per agent in order, `steered` on one that joined a running turn; a copy that couldn't go is `{"agent", "status": "failed", "why", "ref"}` and the others still go. `gathr.chat.send` carries `gathr.send.agents`. A pick that isn't inside the text, cuts a character in half, doesn't start with `@`, is `@` alone, overlaps another, or names an agent that isn't known is refused (400, with the reason and a reference). The person's message in history and on the live `message` carries its `picks`, in text order; every other message, a message with no pick and one saved before they were kept have `null`.
  - A reply in a thread ([0076](decisions/0076-replying-in-a-thread.md)): the send also takes `reply_to` (the message it answers: a text message of the chat, Gathr's copy of a message standing for the message it carries) or `reply_task` (the task it is about), never both. Anything else is refused before anything is saved (400 "Send failed", with why and a reference: `No message <id> in this chat.`, `<id> is a step, not a message: a reply answers a message's words.`, `No task #<n> in this chat.`, `A reply answers one message or one task, not both.`). The message keeps both fields, in history and on the live `message` (null on every other message); its turn opens with the `reply` kind (`The person replies to your message (message <id>, <time>): "<words>"`, or `The person replies about your task #<n> "<title>".`) before the person's words, serves the ask of what it answers and never starts one, and its `topic` is that thread's. Into the agent's running turn in the chat, as a message goes, the same line goes in with the words.
  - Projects: `GET /api/projects` (`{"projects": [...]}`), `POST /api/projects {"name", "folder", "members"}` (names unique ignoring case; the folder a full path in a git repository). `PATCH /api/projects/<id> {"name", "folder", "members", "ci", "merge"}` changes only what it names, each checked as at creation (0043): `ci` whose result gates a merge, `ci`, `gathr`, `both` or `none` (a clean review alone, 0045; Settings' Review only) (a new project is `ci` when its checkout has a `.github/workflows/*.yml`, else `gathr`; one made before this is `gathr`); `merge` `fast-forward` (the default), `merge` or `squash`. Each project answers `ci_by` and `merge_by` (`source`: an agent's id or `person`; `set`), null until someone sets it. A new folder or team applies to chats made from then on. `checks` in it is refused: the person never types a check (owner, task 1455). Each project answers its `checks` in order, each with its `command`, `source` (the agent that set it, or `found`) and when it was `set`. Each change is a `gathr.project.change` event (which fields) and live `{"type": "project", "project", "change": "changed"}`; a refusal answers `Project settings failed` with a reference. In a project chat each agent's engine runs in its own worktree, in its folder in the agent folder ([api-tasks.md](api-tasks.md)), made at its first turn from the remote's default branch, fetched then. To try it without the network, make the project a local clone: its `origin` is the folder it was cloned from.
  `DELETE /api/projects/<id>` deletes it at once ([0069](decisions/0069-deleting-a-project-or-an-agent.md)): each of its chats, archived ones too, as a chat's delete does, then its rows, then its own folders in the agent folder (each agent's folder, `checks`, `caches`); `Shared`, the project's folder and the person's checkout stay. It answers `{"deleted": true, "chats", "tasks", "projects", "leads", "left"}`, `left` naming each folder that couldn't go yet with its reference; the sweep tries it again at each look. `GET /api/projects/<id>/delete` answers the same counts before. Recorded as `gathr.project.delete` and `gathr.project.files`; live `{"type": "project", "project", "change": "deleted"}`. A check run under way isn't ended: its results are lost with the project, and its checkout goes at a later sweep.
  - Open at login: `GET /api/startup`, `PUT /api/startup {"on"}` (Settings > General), read from the system each time: a value in the person's `Run` key on Windows (off when Task Manager turned it off), a LaunchAgent in `~/Library/LaunchAgents` on macOS. It starts `gathr-app` with `--hidden`, so Gathr opens in the tray: the one beside the service, else the one beside the installed `gathrd` the window last opened the folder from (`<data>/app/installed`), as the service runs from the folder's copy. A test folder's entry has its own name and its `--data`, never the person's own: turn it off when the check is done.
  - Live: a WebSocket at `/api/live?token=<token>` sends every delta (with `at`, where it starts in the turn's unsaved text, in UTF-16 units, so a window that read `streaming` skips what it already has), message, tool, turn, approval and read, as JSON; `{"type": "chat", "chat", "change": "created"}` and `{"type": "project", "project", "change": "created"}` when one is made, so every open window lists it; `{"type": "chat_state", "chat", "working", "needs", "mark"}` when a chat starts or stops working or needing the person, or its row's mark changes, only when one of them changed, as its row in `GET /api/chats` has them (0040: also after an approval is answered, in whichever window; 0052: when the person is told a chat isn't moving, which arrives as a `message` with role `gathr` and no turn, and when that stretch ends); `{"type": "members", "chat"}` when a chat's agents change, and `{"type": "tasks", "chat", "tasks", "waits", "asks", "plans", "caught"}` (as `GET /api/chats/<id>/tasks` answers, the asks and their size too, with `held` on each, [0061](decisions/0061-every-ask-has-a-size.md) and [0063](decisions/0063-building-waits-for-a-new-asks-plan.md), the chat's plans, [0062](decisions/0062-a-plan-is-checked-and-approve-hands-it-out.md), and `caught`, the message ids of Gathr's lines for a change caught in a held turn, oldest first, [0063](decisions/0063-building-waits-for-a-new-asks-plan.md)) after every change to a chat's tasks, waits, asks or plans (a plan's version added or changed), then `{"type": "person_tasks", "tasks"}` (as `GET /api/person-tasks` answers); `{"type": "pauses"}` (as `GET /api/pauses` answers) after a pause, resume, usage hold or a pause going quiet; `{"type": "waiting", "chat"}` whenever what the chat waits on may have changed, a pause, a resume, the person's message and a turn going silent or making progress again among them ([api-tasks.md](api-tasks.md)); `{"type": "reaction", "chat", "reaction"}` when an agent gives a message its thumbs-up, or the person their like, for the first time, `reaction` as in the history (a repeat sends nothing), and the same with `"removed": true` when the person takes theirs back; `{"type": "reads", "chat", "reads"}` after each kept write of where the person left off, `reads` its rows as kept, to every window; a held turn's `{"type": "turn"}` carries `held`, and every one carries when the turn was made (`created`) and, once it has started, its `position`, as `GET /api/chats/<id>` has them, so a live window shows and orders turns as a reload would.
  - Search ([0035](decisions/0035-search.md)): `GET /api/search?q=<text>&archived=<bool>&limit=<n>` answers `{"chats", "messages"}`: up to 8 chats whose title holds `q` (`chat`, `title`, `project`, `archived`, `time` last active), then text messages holding every typed word as a word start, case and accents ignored, newest first (`limit` 30 by default, at most 100), each with `chat`, `chat_title`, `archived`, `message`, `role`, `agent`, `time`, `snippet` and `marks` (`[start, end]` in UTF-16 units). Archived chats are in, marked, unless `archived=false`. `q` is cut at 200 characters; an empty one finds nothing. Each request is a `gathr.search.query` event (`chars`, `words`, `chat_hits`, `message_hits`, `archived`, never the words). To time it, seed a folder 20 times (about 11k messages). To force a failure, drop `message_search` in a stopped test folder's database: the next search answers with a reference that `diag trace` finds.
  - Context (the room's `Shared/archive/2026-11/plans/compaction.md`, K1): each member in `GET /api/chats/<id>` has `context: {used, window, compact_at}` (null before the agent's first call in the chat; when the engine opens a new conversation for a task, `used` is null until its first call; when it resumes one, `used` is that conversation's last fill from the moment it opens, read from the `task_sessions` row that holds its session, so a fix that resumes its PR's work task shows that task's fill (0055, N7)): `used` is the agent's last main-session model call's prompt in tokens (Claude Code: an assistant message's input + cache read + cache write; Codex: `thread/tokenUsage/updated`'s `last.inputTokens`; a sub-agent's never counts), `window` its model's (Claude's result `modelUsage[model].contextWindow`, Codex's `modelContextWindow`), kept per chat in `agent_context`; live `{"type": "context", "chat", "agent", "context"}`. A compaction (Claude's `system/compact_boundary`, Codex's `contextCompaction` item) sets `used` to its size after when the engine gives one, leaves "Compacted Ann's conversation: 23K to 3.6K" (no sizes for Codex) in the turn and records `gathr.context.compact`. An agent's panel shows it as the registry's context display, a track and the percent, saying New while `used` is null (DESIGN.md "Agent panel"). `tests/frames/compact_claude.jsonl` and `compact_codex.jsonl` were recorded once each on test accounts with a local build: slash commands on for a `/compact`, and Codex's `model_auto_compact_token_limit` at 2000.
  - Auto-compact (K3): `GET`/`PATCH /api/settings {"auto_compact"}` (Settings > General): 200000, 300000, 400000 or 500000 tokens (500000 by default), or `null` for each engine's own. `compact_at` is that, never past 80% of the agent's model window. Each engine gets it as it starts, and members show it, for every agent, on a pinned model, a Latest or its engine's default alike, once the engine has named the model the agent's calls run on and shown its window while the agent was set as it is now on the same account (in that chat, else its latest anywhere; `agent_context.window_of` is what the agent was set to, `ran` the model named: Claude Code's on each call, Codex's as its thread opens). Until then, and after the agent's model or account changes, the engine compacts at its own point. A Latest or an engine's default can become another model: when the engine names another model than its point was for, the windows seen on the old one give no point again (`gathr.context.moved`, with `from` and `to`) and the engine closes before the agent's next turn, to start with the point the new model's own window allows; a Codex Latest that resolves to another model opens its thread without the point at once. Claude Code 2.1.322 itself uses the smaller of the point and its model's window. A changed setting applies from each engine's next start. Claude Code gets it as `CLAUDE_CODE_AUTO_COMPACT_WINDOW` (at least 100000, its floor), Codex as `model_auto_compact_token_limit` in the thread's config. When the last call filled 75% of `compact_at`, the agent's next turn starts with one line telling it to write down what it still needs in its own folder (`gathr.context.soon`); once, then again only after a compaction or a failed turn (`agent_context.told`).
  - Compact (K4): `POST /api/chats/<id>/agents/<agent>/compact` answers `{turn, status, ref}`: `running`, or `queued` behind the agent's turn under way, its engine's background commands and the turn the engine starts when they end. It's a turn of its own with no ask; a turn queued after it waits for it, and nothing is sent into it. Claude Code runs `/compact` in an engine started without `--disable-slash-commands` (the agent's next turn starts it again with them off); Codex gets `thread/compact/start` on its open thread. Success leaves the quiet line above and `gathr.context.compact` with `trigger: manual`. A turn that ends without a compaction fails with "Couldn't compact Ann's conversation: <why>" and its reference. Refused (409, with a reference, `gathr.context.compact` with `error: refused`): no conversation yet (no saved session and no turn of the agent in the chat), or one compacting already. `tests/frames/compact_codex_asked.jsonl` is a real one on a test account (Codex 0.167.2: `thread/compact/start` answers `{}`, then a turn holding one `contextCompaction` item). Timed live on test accounts with a local build: 7.9 s from the request for Claude Code 2.1.322 (its engine restarted with slash commands on), 6.1 s for Codex; each agent still knew a word from before it.
  - Diagnostics: `GET /api/chats/<id>/turns`, each turn with what was asked and its events in order.
  - The window's own events: `POST /api/ui/events {"name": "gathr.ui.…", "duration_ms", "error", "attrs"}`, recorded like the service's (UI errors, open and switch timings, first text shown).
