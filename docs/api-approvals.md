# The API: approvals and Gathr's tools

Part of [AGENTS.md](../AGENTS.md)'s Run, use and check it; the other parts are listed there. The API's address and sign-in are in [api.md](api.md).

- Approvals ([0029](decisions/0029-approvals.md)): an agent's `approvals` is `ask`, `edits`, `auto` (the default) or `full`, Claude Code's Manual, `acceptEdits`, `auto` and `bypassPermissions`. In every mode but `full`, Claude Code asks Gathr's hook at `/hook` (the engine's own token only) before each file write and command, and it answers "ask" for a push command that may force, delete or skip the push hook, a file write outside the agent's folders (the one it runs in, its own and its project's Shared; links followed), or, in Manual and `edits`, a `wait` with a check, which Gathr runs itself: `gathr.approvals.ask`. A held turn's file write into its worktree (`Write`, `Edit` or `NotebookEdit` with a path inside it) is refused too, in every mode ([0063](decisions/0063-building-waits-for-a-new-asks-plan.md)): in `ask`, `edits` and `auto` the hook reads the hold after the check above and answers `deny`; in `full` Claude Code asks the hook only before those three tools, at `/hook?full`, with the same token and no `onFailure`, and it answers only the hold: `deny` for a held write, and otherwise `{}`, never `ask` and never `allow`, so Full never asks the person and a Gathr that can't answer lets the write go on. The reason names the worktree and says to write notes and mock-ups in the agent's own folder or Shared, which stay writable (a missing one reads "your own folder" or "Shared"); for the chat's Supervisor a clause follows, by the ask's open plan: "If it is a repair, size it repair with size." (no open plan, ask not sized by the person), "Its plan is being checked: building starts once the person approves it.", "Its plan waits for the person's Approve: tell them so, and don't write it again." or "Write the next version of its plan with plan."; for a look-into task, "Task #12 is a look-into task: don't change files in <worktree>. ...". The hook reads the hold in one writer job of at most 5 s: a timeout, a stopped writer or a SQLite error reads as not held, the write goes on, and `gathr.hold.read` is recorded with `error` `timeout`, `writer` or `sqlite`, `why` and `gen_ai.agent.id`, because the hook in the other modes blocks a call it can't reach. A refusal is `gathr.hold.refused` on the turn's trace (`gathr.ask.id`, `gathr.turn.id`, `gen_ai.agent.id`, `gathr.hold.what` `write`, `gathr.hold.why` `unplanned` or `look_into`, `gathr.hold.plan` when the ask has an open plan, `gen_ai.tool.name`) and sets the ask's `held_ts`. A shell command's writes and Codex's file writes are not refused: Codex asks Gathr only where its sandbox makes it, and a file-change request names a grant root, not the files. Both go on, and a held turn's change to its worktree is caught at the turn's end and shown (`gathr.hold.look`, `gathr.hold.changed`, `gathr.hold.told`: [api-tasks.md](api-tasks.md)). In `auto` a wait's check is the engine's own to judge, as the agent's commands are, and the person isn't asked (owner, 2026-11-11): `wait` isn't on Claude Code's allow list, so its classifier reads the call, and Codex is told to ask for approval of `wait` (`mcp_servers.gathr.tools.wait.approval_mode`), which its automatic reviewer answers; the check's `gathr.approvals.check` event says `allowed_by: "Claude Code auto mode"` or `"Codex auto review"`, and a block by Claude Code's classifier is `gathr.approvals.blocked`. A check that is one read-only command (`gh pr view`, `gh pr checks`, `git log`, `git rev-parse`, by those names, made only of letters, digits, spaces and `-_./:=%,@+^~`, with none of their options that write a file, open a browser, name another repo or, for `git log`, print a diff, stat or signature or use a format the repository defines) doesn't ask; it runs as those words without a shell, with git's pager, signature check and default format switched off over the repository's config (`gathr::approvals::read_only_env`). `git status` isn't one: it runs any filter the repository names, from `.git/info/attributes` and `core.attributesFile` too, so it asks; for Claude Code and Codex alike (0043 C11, `gathr::approvals::read_only_check`); its `gathr.approvals.check` event says `allowed_by: "read-only: <command>"`. Every `git push` from an agent's worktree, whatever the engine and mode, also goes through git's `pre-push` hook (in `<data>/hooks/<chat>/<agent>`, set as that worktree's own `core.hooksPath`), which sends its refs to `/hook/push` with `GATHR_AGENT_TOKEN` and `GATHR_PUSH_URL`: a held turn's push is refused first (the answer `held: "<the ask>" has no approved plan, so nothing is pushed for it`, or `held: a look-into task pushes nothing`, which the script prints as `Gathr: the push wasn't allowed (<answer>)`; `gathr.hold.refused` with `gathr.hold.what` `push` and no `gen_ai.tool.name`; a hold that can't be read in 5 s lets the push go on to the checks below, as `gathr.hold.read`), and otherwise a push to the remote's default branch, a force push, a branch deletion or a push to anywhere but the worktree's `origin` waits as an approval named `git push`, saying why; any other push goes through (the owner's "Ask only for risky pushes"). Either way it's `gathr.approvals.push`, an ordinary one with `allowed_by`. To push by hand as an engine, run git in the worktree with those two variables from the replay engine's `GATHR_REPLAY_ENV` file. A block by auto mode's own check is `gathr.approvals.blocked`; an engine that started in another mode (auto isn't offered for every model) is a `gathr.approvals.mode` error. To try it live, point the test project's push URL at a bare repo first (`git remote set-url --push origin <bare>`), so an approval allowed by mistake never pushes anywhere real.
- Gathr's tools: an MCP server at `/mcp` (Streamable HTTP) that takes only a running engine's own token, never the service's. Each engine gets one in `GATHR_AGENT_TOKEN`, and it ends when the engine exits; a tool acts as that engine's agent in its chat, and each call is a `gathr.tool.call` event on the turn's trace. Tools: `read_chat` (a message over 1,900 characters shows its first 1,500 and last 400, with where it was cut and its id; `message` reads it whole, G176), and for tasks and waits `give_task`, `edit_task` (below), `finish_task`, `list_tasks`, `cancel_task`, `restart_task`, `wait`, `end_wait`, `message` (one member of a team chat, below), `react` (below), `size` (below), and `ask_person` for anything an agent needs from the person; for a project chat's Supervisor, `checks` (the project's checks with who set each, and `found`: what its package.json, Cargo.toml, pyproject.toml and `.github/workflows` `run:` steps name) and `set_checks` (any of `checks`, which replaces the list, `ci` and `merge`, each recorded with the Supervisor as who set it, as Settings records `person`; a command not in `found` asks the person once per project, as an approval named `project checks`, then never again there; a member is refused with a reference; `gathr.checks.set`); for any agent, when the person asks (0043 C5a), `settings` (Settings > General, agents, projects), `set_settings` and `set_agent` (recorded with `by`, on `gathr.settings.change` and `gathr.agent.change`), `answer_approval` (another agent's open approval in the chat, `gathr.approvals.answer`) and `answer_person` (one of the person's questions in the chat, its line saying who answered for the person). Refused with a reference: an agent's own approval, its own question to the person (or one filed for it), and moving any agent into or out of Full approvals, which decides which pushes ask.; for any agent in a project chat, GitHub as Gathr reaches it with its own `gh` sign-in on this computer ([0046](decisions/0046-github-tools.md)), so an engine's sandbox needs no GitHub login: `pr {"pr"}` (state, head, base, mergeable, review and each check on its head), `ci_failures {"pr"}` (each failed GitHub Actions check: its log up to its last error, its last 40 lines, and its first 10 annotations, secrets hidden; another CI's failed status by its context and link) and, for the PR's reviewer only, `update_pr {"pr", "head"}` (GitHub's Update branch, pinned to `head`: refused for a head that moved, a closed PR or one not into the default branch, read again just before the write and checked after it; `gathr.github.update` records the head requested and returned). Each runs fixed arguments in the project's own folder, never a command or repository an agent names, and `GH_DEBUG` is dropped so no HTTP traffic reaches an answer. A failure says whether Gathr has no GitHub sign-in or this account can't reach the repository. `GATHR_LIVE_PR=<n> cargo test -p gathr --test github -- --ignored` reads a real PR, changing nothing. For any agent, `diag {"command", "since", "reference"}` ([0019](decisions/0019-troubleshooting.md)): `health`, `failures` (`since`, 24h unless set, above zero) or `trace` (a reference), the command line's own answers with only the caller's chat's events and events of no chat; `health` shows only that chat's open tasks, waits, held turns and busy chats. The whole answer is redacted, a trace lists its errors first, and an answer over 16,000 characters is cut, with a last line that says how much. A refusal answers `<tool> failed: <why> (ref …)`. Each engine's briefing is a file in `<data>/briefings` while it runs, and each turn's `invoke_agent` start event records what Gathr gave it (`gathr.context.briefing.chars`, `gathr.context.ask.chars`, each with a `tokens_estimate`, and `gathr.tools.off`); a message sent into the turn adds its size on a `gathr.turn.read` event when the engine reads it, and Diagnostics shows the sum. To call the tools by hand, run the replay engine with `GATHR_REPLAY_ENV` set to a file: each start appends its token there.
- Friction ([0048](decisions/0048-gathr-records-friction.md)): `report_friction {"what", "where"}` keeps what got in an agent's way (`what` up to 500 characters, `where` optional, up to 200), with the agent, the chat, the turn, its task and the time; it answers `Recorded as friction #<n>.` and wakes nobody. `GET /api/friction` lists the 200 newest (`id`, `time`, `chat`, `chat_title`, `agent`, `agent_name`, `task`, `what`, `where`; a deleted chat or agent leaves its title or name null), Settings > Diagnostics shows them under the turns, and `gathr diag friction --since 30d` reads them without the service. The event is `gathr.friction.report`.
- Task briefs ([0059](decisions/0059-a-work-task-carries-a-complete-brief.md)): `give_task {"to", "what", "why", "done", "proof", "where", "size", "lines", "after", "kind", "pr", "in_passing", "look_into"}` takes the kinds `work` and `review`. A work task needs `why`, `done`, `proof` and `where`, and the refusal names each one missing; a review takes none of `done`, `proof`, `where` or `size`. `size` and `lines` go together, and `lines` is 1 or more. Each field's limit is in the tool's schema as `maxLength` (`what` 80, `done` and `proof` 300, `where` and `size` 200) and `minimum` (`lines` 1), and a field over it is refused saying how many characters to cut, with the details going in `why`. `edit_task {"task", "what", "why", "done", "proof", "where", "size", "lines", "after"}` changes only what it names, and only on a task its caller gave, until its first turn starts: an empty `size` removes the size and its lines, and `after` replaces the list. It is refused, with a reference, for a task that has started ("message the owner or cancel it"), one that isn't waiting, ready or blocked, a question for the person, a chat that is archived, a field that fails the rules above, an `after` that names a task outside the chat, itself or a loop, and an edit that changes nothing. It answers "Task #3 edited (what, done): ready.", "... waiting on #1, #2." or "... blocked (<reason>).", and writes `gathr.task.edit` with the fields and their old values. A ready task, whose turn is queued with its brief, has that brief rewritten in place; the window's task view and plan show the change live (the chat doesn't draw a task's own brief). A ready task that an edit makes wait drops its queued turn, and queues a new one when it's ready again: the dropped turn leaves the task as the edit left it, and its giver hears nothing of it. A review with a `pr` is refused while a review of that PR in the chat is waiting, ready, working or held ([0060](decisions/0060-gathr-gives-the-review-task.md)): `PR #7 already has an open review: #2, Bo's, given by Ann. Give one once #2 has ended or its giver cancels it.` A review of a PR whose reviews have all ended or been cancelled, and a review with no `pr`, are taken. `look_into` ([0063](decisions/0063-building-waits-for-a-new-asks-plan.md)) is for a task that only looks into something (research, a feasibility check, options, mock-ups): it never changes the project's files or pushes, and it can be given before an ask's plan is approved. Its brief says so. It is refused, with a reference, on a review ("A review isn't a look-into task: leave out look_into, or give it as work.") and with a `pr` ("A look-into task takes no pr: it changes nothing."), and records nothing of the hold. A work task that isn't a look-into task, given from a held turn (in a chat of two or more agents, the turn of a look-into task, or a turn with no building task on an ask that isn't a repair and has no approved plan), is refused, with a reference, saying what to do instead: for the lead, by the ask's open plan (`plans::open_state`), one of: "... has no approved plan, so building waits. If it is a repair, size it repair with size; else write its plan with plan, or give a look-into task (look_into: true) for what the plan needs first." (the repair clause only when the person hasn't sized the ask), "... its plan is being checked, and building starts once the person approves it. Meanwhile give a look-into task ...", "... its plan waits for the person's Approve. Tell them so, and don't write it again.", or "... its plan was sent back or its check found problems. Write the next version with plan."; for another member, to give a look-into task or tell the lead what it found; for a look-into task's turn, "Task #n is a look-into task, so it gives no building work: give a look-into task (look_into: true), or report what you found." The refusal records `gathr.hold.refused` (`gathr.hold.what` `give`) and sets the ask's `held_ts`. A building task's own turns are never held, so a member on a started task can still give: its new task is taken and, on a held ask, waits for the plan. A work task given on a held ask by Gathr itself (0053's fix, Approve's tasks) is never refused: it is taken, and waits for the plan with no turn while its ask is held. The answer for a task that waits for its plan reads "Task #3 for Ann: waits for its plan.". Review and plan-check tasks pass the hold. `finish_task` on a look-into task refuses a `pr`: "Task #n is a look-into task: it names no PR. Put what you found in note, or the file you wrote in file." `size` and `plan` are never held; `size` returns the turns of the tasks it puts back in line, which the service starts.
- Size ([0061](decisions/0061-every-ask-has-a-size.md)): `size {"size", "message"}` records the size of the person's ask the caller's turn serves, `repair` or `new` (a string, so a wrong value gets Gathr's refusal and its reference), for the chat's Supervisor only. With `message`, the id of a message of the person's as `read_chat` gives it: the ask that message started, or, for a message that joined another ask, an ask of its own, split off and sized. It answers `Sized "<title>" as <size>.`, `Made message <id> an ask of its own and sized "<title>" as <size>.` or `"<title>" is already <size>.`. Refused with a reference, in this order, nothing written: a size that isn't repair or new (`` `<size>` isn't a size: give repair or new. ``), an archived chat, a chat with one agent (`This chat has one agent, so its asks have no size.`), a caller who isn't the Supervisor (`Only <lead>, the chat's Supervisor, sizes asks.`), no turn running in the chat, a `message` that isn't a message of the person's in this chat, a `message` that serves no ask (it came before asks, or before the chat had two agents), no `message` and a turn that serves no ask, and an ask the person sized last when the lead asks another size (`The person made this ask <size>: only the person changes it now.`). Each change is a `gathr.ask.resized` event on the turn's trace ([api-tasks.md](api-tasks.md)). The briefing names `size` beside `react`. To see it without a login, hold the replay engine and call `size` with a member's token for the refusal, as in `tests/sizes.rs`.
- Plans ([0062](decisions/0062-a-plan-is-checked-and-approve-hands-it-out.md)): `plan {"title", "text", "parts", "answers"}` writes the next version of the plan for the ask the caller's turn serves, for the chat's Supervisor only. `title` is one line of at most 80 characters, `text` says what the plan does and why, and each of `parts` (numbered from 1, in order) is a task as `give_task` gives one: `to` (an agent by name), `what`, `why`, `done`, `proof`, `where`, `size`, `lines`, and optionally `after` (earlier parts, by number) and `after_tasks` (tasks of the chat). Each part goes through the same checks as a task's brief, its refusal prefixed "Part <n>: ". `answers` (`note`, `changed`, `why`) answers each finding of the last check and only then. The version is the caller's own message, whose body is the whole plan ("Plan: <title> (version <n>, <k> parts)", the text, then each part with its fields as a task's brief reads them), so `read_chat` reads it and `react` agrees with it. Gathr gives the check in the same transaction and answers `Wrote version <n> of plan #<id>, "<title>": <k> parts. <checker> checks it in #<task>; the person sees it after.` Refused, in this order, as `plan failed: <why> (ref ...)` and nothing written: an archived chat; a chat of one agent; a caller who isn't the Supervisor; no turn running; a turn that serves no ask of the person's; an ask sized `repair`; a question of the lead's to the person still open for the ask (Gathr's own questions about a PR aren't counted); a title that isn't one line of 1 to 80 characters; no parts; a part that isn't a whole brief, has no `size` or `lines`, names an agent who isn't in the chat, comes after a part that isn't earlier, or after a task that isn't the chat's or is cancelled; two parts with the same `what`; `answers` where the version before has no check that left findings, a note that isn't one of them, or a finding left unanswered; a version equal to the one before with no `answers`. While a question of the lead's to the person is open for an ask with no approved plan, a second one is refused until it is answered or cancelled. The open plan of the turn's ask gets the version; with none, a new plan is made, and a plan whose versions are all approved or dropped starts a new one. The briefing names `plan` beside `size`.
- A plan's check ([0062](decisions/0062-a-plan-is-checked-and-approve-hands-it-out.md)): a review task with `checks` set, given by Gathr to the lead's checker: the one who objected to the version before, else the chat's Reviewer, else the free member that has checked least. Its brief is a kind of Gathr's words (`plan_check`, 0056): the ask, the plan with its message id and how to agree; after findings, only that checker's findings with the lead's answers. A thumbs-up from the checker on the version's message with `react` finishes the check as done (`nothing_unasked`) with no second call, and `react` answers `Your check #<n> of version <v> is done.` or, while its turn runs, `Recorded: your check #<n> of version <v> is done when the turn running on it ends.`; a thumbs-up from anyone else, or on an older version, is a plain reaction. Objecting is `finish_task` `left` with at least one `wrong` or `unasked` note, each with its evidence in `says`; suggestions alone are refused for a check, and so are `pr`, `commit` and `signed_off`. No fix is given to anyone for a left check; the lead hears of it at once, with the findings in its reason, and must answer each in the next version's `answers`.
- Thumbs-up ([0057](decisions/0057-agreeing-is-a-reaction.md)): `react {"message"}` puts the agent's thumbs-up on another agent's message in its own chat, by the id `read_chat` or a message to it gives. The id may be Gathr's copy of a teammate's message: the thumbs-up lands on the message it carries. It is one row in `reactions` and a `gathr.message.reaction` event (`message`, `agent`) on the turn's trace, with a live `{"type": "reaction"}` ([api.md](api.md)); it posts no message, counts no hand-off and wakes nobody. A second one from the same agent on the same message changes nothing, writes no event and answers that the message already has it. Refused with a reference: no turn running in the chat, no text message with that id in the chat, a message that isn't an agent's (the person's, Gathr's own lines), the agent's own message, an archived chat. Deleting a chat deletes its reactions. The window draws the icon and a count under the message, and the names on hover and focus. To see it without a login, hold the replay engine and call `react` with a member's token, as in `tests/messages.rs`.
- Agents message each other (the room's `Shared/archive/2026-11/plans/agent-messages.md`; 0010's hand-off counter): `message {"to", "text"}` (a member by name, matched as the person's `@Name`, up to 500 characters) is saved as the sender's message on its turn, with `to` (the member's id) in `GET /api/chats/<id>`, and sent live; what Gathr tells the member in its turn reads "<sender> wrote to you (message <id>): <text>" and has `copy_of` (that message's id), so the window shows the words once: the sender's, as their own block headed "<sender> to <member>" where they were sent (0037), with the member's turn it wakes after it. Settings > General's Pause after picks the limit (5, 10, 25, 50 or No limit). To see it without a login, hold the replay engine and call `message` with the Supervisor's token, as in `tests/messages.rs`. It wakes the member at most once: into the turn it runs in that chat, else into its turn queued there that hasn't started, else one turn of its own on no task, answering the sender's turn (a pause holds it as any turn Gathr queues). Refused with a reference: the sender itself, a name not in the chat, a chat of one agent, an archived chat. Each message is a hand-off record (`handoffs`): its depth is the sender's chain plus one, starting over after the person's message in the chat or a task there settling; past the limit (`handoff_limit` in `GET`/`PATCH /api/settings`, 50 by default, 1 to 1000, `null` for none) the message still shows, nobody is woken, and the chat is paused ("Paused after 50 hand-offs between agents. Resume to carry on."). Events: `gathr.message.send` (`from`, `to`, `chars`, `depth`, `delivered`: `in_turn`, `joined`, `queued`, `held`, `paused`; never the text) and `gathr.handoff.limit`.
