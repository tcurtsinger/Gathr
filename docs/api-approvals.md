# The API: approvals and Gathr's tools

Part of [AGENTS.md](../AGENTS.md)'s Run, use and check it; the other parts are listed there. The API's address and sign-in are in [api.md](api.md).

- Approvals ([0029](archive/decisions/0029-approvals.md)): an agent's `approvals` is `ask`, `edits`, `auto` (the default) or `full`, Claude Code's Manual, `acceptEdits`, `auto` and `bypassPermissions`. In every mode but `full`, Claude Code asks Gathr's hook at `/hook` (the engine's own token only) before each file write and command, and it answers "ask" for a push command that may force, delete or skip the push hook, or a file write outside the agent's folders (the one it runs in, its own, its project's Shared and its project's part of Designs; links followed): `gathr.approvals.ask`. One Allow of a write outside covers, for that agent in that chat, the top of the git checkout the file is in (the nearest folder at or above it holding a `.git`) and everything under it, or, in no checkout, the files directly in the file's folder; the reason names it ("Allow covers <folder> in this chat."). A later write it covers is answered "allow", so the engine's own mode doesn't ask either: `gathr.approvals.covered` (`folder`). It is kept in memory until the service restarts; a Deny remembers nothing, nothing in the data folder is ever covered, and the folder is worked out again from the approval's own input. Codex asks through its own sandbox and is unchanged. Every `git push` from an agent's worktree, whatever the engine and mode, also goes through git's `pre-push` hook (in `<data>/hooks/<chat>/<agent>`, set as that worktree's own `core.hooksPath`), which sends its refs to `/hook/push` with `GATHR_AGENT_TOKEN` and `GATHR_PUSH_URL`: a push to the remote's default branch, a force push, a branch deletion or a push to anywhere but the worktree's `origin` waits as an approval named `git push`, saying why; any other push goes through (the owner's "Ask only for risky pushes"). Either way it's `gathr.approvals.push`, an ordinary one with `allowed_by`. To push by hand as an engine, run git in the worktree with those two variables from the replay engine's `GATHR_REPLAY_ENV` file. A block by auto mode's own check is `gathr.approvals.blocked`; an engine that started in another mode (auto isn't offered for every model) is a `gathr.approvals.mode` error. To try it live, point the test project's push URL at a bare repo first (`git remote set-url --push origin <bare>`), so an approval allowed by mistake never pushes anywhere real.
- Gathr's tools: an MCP server at `/mcp` (Streamable HTTP) that takes only a running engine's own token, never the service's. Each engine gets one in `GATHR_AGENT_TOKEN`, and it ends when the engine exits; a tool acts as that engine's agent in its chat, and each call is a `gathr.tool.call` event on the turn's trace. Tools: `read_chat` (a message over 1,900 characters shows its first 1,500 and last 400, with where it was cut and its id; `message` reads it whole, G176), `react` (below), `set_board_line` and `ask_person` for anything an agent needs from the person; for any agent in a project chat, GitHub as Gathr reaches it with its own `gh` sign-in on this computer ([0046](archive/decisions/0046-github-tools.md)), so an engine's sandbox needs no GitHub login: `pr {"pr"}` (state, head, base, mergeable, review and each check on its head), `ci_failures {"pr"}` (each failed GitHub Actions check: its log up to its last error, its last 40 lines, and its first 10 annotations, secrets hidden; another CI's failed status by its context and link) and `update_pr {"pr", "head"}` (GitHub's Update branch, pinned to `head`: refused for a head that moved, a closed PR or one not into the default branch, read again just before the write and checked after it; `gathr.github.update` records the head requested and returned). Each runs fixed arguments in the project's own folder, never a command or repository an agent names, and `GH_DEBUG` is dropped so no HTTP traffic reaches an answer. A failure says whether Gathr has no GitHub sign-in or this account can't reach the repository. A refusal answers `<tool> failed: <why> (ref …)`. Each engine's briefing is a file in `<data>/briefings` while it runs, and each turn's `invoke_agent` start event records what Gathr gave it (`gathr.context.briefing.chars`, `gathr.context.ask.chars`, each with a `tokens_estimate`, and `gathr.tools.off`); a message sent into the turn adds its size on a `gathr.turn.read` event when the engine reads it, and Diagnostics shows the sum. To call the tools by hand, run the replay engine with `GATHR_REPLAY_ENV` set to a file: each start appends its token there.
- Friction ([0048](archive/decisions/0048-gathr-records-friction.md)): what agents reported got in their way, before the friction tool went. `GET /api/friction` lists the 200 newest (`id`, `time`, `chat`, `chat_title`, `agent`, `agent_name`, `task`, `what`, `where`; a deleted chat or agent leaves its title or name null), Settings > Friction lists them, and `gathr diag friction --since 30d` reads them without the service.
- The open check ([0080](archive/decisions/0080-the-team-checks-the-leads-answer-in-the-open.md)): once per message of the person's or answer of theirs to a question, when the lead's newest turn since it has ended well with words and no turn of the chat runs or is queued, Gathr queues a turn for each member but the lead who is free and took no part since the person wrote, opened by its words of kind `check` (0056) and answering the lead's turn, in a chat of two agents or more. The words carry the person's message, or Gathr's line with their answer, and the lead's answer. A member agrees with `react` on the answer and writes only `NO_REPLY`, which posts nothing; `react` then answers `Gave <id> a thumbs-up. That is your whole check: end your turn with only NO_REPLY.` Words with no thumbs-up question the answer: once every check turn has ended, the lead gets one turn of kind `last_word` with each one's words as `Name: words`, unless the person has written again since. When the round ends (with no checker, at once; else after the checks and any last word) `gathr.check.round` records `gathr.check.asked`, `agreed`, `objected`, `silent`, `last_word`, `gathr.message.id` and `gathr.turn.id`.
- Thumbs-up ([0057](archive/decisions/0057-agreeing-is-a-reaction.md)): `react {"message"}` puts the agent's thumbs-up on the person's message or another agent's in its own chat, by the id `read_chat` or a message to it gives, by `person`: the last message of the person's to reach the agent's turn (C5), or in a check turn by `answer`: the answer it checks ([0082](archive/decisions/0082-a-message-reads-as-serenityos-card.md)), refused with "only a check has an answer to agree with" in any other turn. The id may be Gathr's copy of a teammate's message or of the person's: the thumbs-up lands on the message it carries. The answer names the message it is on. It is one row in `reactions` and a `gathr.message.reaction` event (`message`, `agent`) on the turn's trace, with a live `{"type": "reaction"}` ([api.md](api.md)); it posts no message, counts no hand-off and wakes nobody. A second one from the same agent on the same message changes nothing, writes no event and answers that the message already has it. Refused with a reference: no turn running in the chat, no text message with that id in the chat, Gathr's own line, the agent's own message, `person` when the turn has no message of the person's, an archived chat. Deleting a chat deletes its reactions. The window draws the icon and a count under the message, and the names on hover and focus. To see it without a login, hold the replay engine and call `react` with a member's token, as in `tests/messages.rs`.
- `@Name` in an agent's words ([0081](archive/decisions/0081-agents-hear-the-room-and-name-each-other.md)): when an agent's turn ends done, each member its text messages name with `@Name` (ignoring case, longest name first, a whole word only, so `bob@ann.com` names nobody; never itself, never a name that isn't a member's; in a chat with no project, any agent of the person's, which joins it as a member in a `members` change, unless the chat already has 5) is woken once: into its running turn in the chat, joined to its turn queued there, or a turn of its own answering the sender's. What Gathr tells it reads "<sender>: <words>", the sender's messages that name it, and has `copy_of` (the first of them), so the window shows the words once and the woken turn sits in that message's thread. Each is a hand-off record (`handoffs`): its depth is the sender's chain plus one, starting over after the person's message in the chat; past the limit (`handoff_limit` in `GET`/`PATCH /api/settings`, 50 by default, 1 to 1000, `null` for none; Settings > Teamwork's Pause after) nobody is woken and the chat is paused ("Paused after 50 hand-offs between agents. Resume to carry on."); the pause line goes in the sender's turn. Events on the sender's turn's trace: `gathr.message.mention` (`from`, `to`, `message`, `depth`, `delivered`: `in_turn`, `joined`, `queued`, `held`, `paused`; an error `sqlite` with `why` when the wake failed and nobody was woken) and `gathr.handoff.limit`. To see it without a login, make the replay engine say `@Ann` instead of its "Hi!", as `tests/mentions.rs` does.
- What a turn hears of its team chat ([0081](archive/decisions/0081-agents-hear-the-room-and-name-each-other.md)): in a chat of two or more agents, what Gathr sends an agent as its turn opens (never saved) starts with the chat's lines as `Name: words` (`Person`, `Gathr`, or the agent's name): in a new conversation, its first turn in the chat, or after a compaction, the last 30 under "Recent lines in this chat:"; otherwise up to 30 that came since its last turn there, without its own and what it already read, under "New in this chat since your last turn:". Never the message that opened the turn, a tool row or Gathr's copy of a message. The lead hears every line whole; a member hears whole the person's lines, Gathr's, the lead's and those that name it, and other members' cut to their first sentence (160 characters at most, ending "…"), with one line saying so. A whole line over 1,900 characters is cut as `read_chat` cuts it. Each turn that hears something records `gathr.room.heard` on its trace (`gathr.turn.id`, `lines`, `chars`, `cut`, `fresh`); a read that fails records it as an error `sqlite`, and the turn goes without the lines.
