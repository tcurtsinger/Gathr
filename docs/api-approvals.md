# The API: approvals and Gathr's tools

Part of [AGENTS.md](../AGENTS.md)'s Run, use and check it; the other parts are listed there. The API's address and sign-in are in [api.md](api.md).

- Approvals ([0029](decisions/0029-approvals.md)): an agent's `approvals` is `ask`, `edits`, `auto` (the default) or `full`, Claude Code's Manual, `acceptEdits`, `auto` and `bypassPermissions`. In every mode but `full`, Claude Code asks Gathr's hook at `/hook` (the engine's own token only) before each file write and command, and it answers "ask" for a push command that may force, delete or skip the push hook, a file write outside the agent's folders (the one it runs in, its own and its project's Shared; links followed), or, in Manual and `edits`, a `wait` with a check, which Gathr runs itself: `gathr.approvals.ask`. In `auto` a wait's check is the engine's own to judge, as the agent's commands are, and the person isn't asked (owner, 2026-11-11): `wait` isn't on Claude Code's allow list, so its classifier reads the call, and Codex is told to ask for approval of `wait` (`mcp_servers.gathr.tools.wait.approval_mode`), which its automatic reviewer answers; the check's `gathr.approvals.check` event says `allowed_by: "Claude Code auto mode"` or `"Codex auto review"`, and a block by Claude Code's classifier is `gathr.approvals.blocked`. A check that is one read-only command (`gh pr view`, `gh pr checks`, `git log`, `git rev-parse`, by those names, made only of letters, digits, spaces and `-_./:=%,@+^~`, with none of their options that write a file, open a browser, name another repo or, for `git log`, print a diff, stat or signature or use a format the repository defines) doesn't ask; it runs as those words without a shell, with git's pager, signature check and default format switched off over the repository's config (`gathr::approvals::read_only_env`). `git status` isn't one: it runs any filter the repository names, from `.git/info/attributes` and `core.attributesFile` too, so it asks; for Claude Code and Codex alike (0043 C11, `gathr::approvals::read_only_check`); its `gathr.approvals.check` event says `allowed_by: "read-only: <command>"`. Every `git push` from an agent's worktree also goes through git's `pre-push` hook (in `<data>/hooks/<chat>/<agent>`, set as that worktree's own `core.hooksPath`), which sends its refs to `/hook/push` with `GATHR_AGENT_TOKEN` and `GATHR_PUSH_URL`: a push to the remote's default branch, a force push, a branch deletion or a push to anywhere but the worktree's `origin` waits as an approval named `git push`, saying why; any other push goes through (the owner's "Ask only for risky pushes"). Either way it's `gathr.approvals.push`, an ordinary one with `allowed_by`. To push by hand as an engine, run git in the worktree with those two variables from the replay engine's `GATHR_REPLAY_ENV` file. A block by auto mode's own check is `gathr.approvals.blocked`; an engine that started in another mode (auto isn't offered for every model) is a `gathr.approvals.mode` error. To try it live, point the test project's push URL at a bare repo first (`git remote set-url --push origin <bare>`), so an approval allowed by mistake never pushes anywhere real.
- Gathr's tools: an MCP server at `/mcp` (Streamable HTTP) that takes only a running engine's own token, never the service's. Each engine gets one in `GATHR_AGENT_TOKEN`, and it ends when the engine exits; a tool acts as that engine's agent in its chat, and each call is a `gathr.tool.call` event on the turn's trace. Tools: `read_chat` (a message over 1,900 characters shows its first 1,500 and last 400, with where it was cut and its id; `message` reads it whole, G176), and for tasks and waits `give_task`, `finish_task`, `list_tasks`, `cancel_task`, `restart_task`, `wait`, `end_wait`, `message` (one member of a team chat, below), and `ask_person` for anything an agent needs from the person; for a project chat's Supervisor, `checks` (the project's checks with who set each, and `found`: what its package.json, Cargo.toml, pyproject.toml and `.github/workflows` `run:` steps name) and `set_checks` (any of `checks`, which replaces the list, `ci` and `merge`, each recorded with the Supervisor as who set it, as Settings records `person`; a command not in `found` asks the person once per project, as an approval named `project checks`, then never again there; a member is refused with a reference; `gathr.checks.set`); for any agent, when the person asks (0043 C5a), `settings` (Settings > General, agents, projects), `set_settings` and `set_agent` (recorded with `by`, on `gathr.settings.change` and `gathr.agent.change`), `answer_approval` (another agent's open approval in the chat, `gathr.approvals.answer`) and `answer_person` (one of the person's questions in the chat, its line saying who answered for the person). Refused with a reference: an agent's own approval, its own question to the person (or one filed for it), and moving any agent into or out of Full approvals, which decides which pushes ask.; for any agent in a project chat, GitHub as Gathr reaches it with its own `gh` sign-in on this computer ([0046](decisions/0046-github-tools.md)), so an engine's sandbox needs no GitHub login: `pr {"pr"}` (state, head, base, mergeable, review and each check on its head), `ci_failures {"pr"}` (each failed GitHub Actions check: its log up to its last error, its last 40 lines, and its first 10 annotations, secrets hidden; another CI's failed status by its context and link) and, for the PR's reviewer only, `update_pr {"pr", "head"}` (GitHub's Update branch, pinned to `head`: refused for a head that moved, a closed PR or one not into the default branch, read again just before the write and checked after it; `gathr.github.update` records the head requested and returned). Each runs fixed arguments in the project's own folder, never a command or repository an agent names, and `GH_DEBUG` is dropped so no HTTP traffic reaches an answer. A failure says whether Gathr has no GitHub sign-in or this account can't reach the repository. `GATHR_LIVE_PR=<n> cargo test -p gathr --test github -- --ignored` reads a real PR, changing nothing. A refusal answers `<tool> failed: <why> (ref …)`. Each engine's briefing is a file in `<data>/briefings` while it runs, and each turn's `invoke_agent` start event records what Gathr gave it (`gathr.context.briefing.chars`, `gathr.context.ask.chars`, each with a `tokens_estimate`, and `gathr.tools.off`); a message sent into the turn adds its size on a `gathr.turn.read` event when the engine reads it, and Diagnostics shows the sum. To call the tools by hand, run the replay engine with `GATHR_REPLAY_ENV` set to a file: each start appends its token there.
- Friction ([0048](decisions/0048-gathr-records-friction.md)): `report_friction {"what", "where"}` keeps what got in an agent's way (`what` up to 500 characters, `where` optional, up to 200), with the agent, the chat, the turn, its task and the time; it answers `Recorded as friction #<n>.` and wakes nobody. `GET /api/friction` lists the 200 newest (`id`, `time`, `chat`, `chat_title`, `agent`, `agent_name`, `task`, `what`, `where`; a deleted chat or agent leaves its title or name null), Settings > Diagnostics shows them under the turns, and `gathr diag friction --since 30d` reads them without the service. The event is `gathr.friction.report`.
- Agents message each other (the room's `Shared/archive/2026-11/plans/agent-messages.md`; 0010's hand-off counter): `message {"to", "text"}` (a member by name, matched as the person's `@Name`, up to 500 characters) is saved as the sender's message on its turn, with `to` (the member's id) in `GET /api/chats/<id>`, and sent live; what Gathr tells the member in its turn has `copy_of` (that message's id), so the window shows the words once: the sender's, as their own block headed "<sender> to <member>" where they were sent (0037), with the member's turn it wakes after it. Settings > General's Pause after picks the limit (5, 10, 25, 50 or No limit). To see it without a login, hold the replay engine and call `message` with the Supervisor's token, as in `tests/messages.rs`. It wakes the member at most once: into the turn it runs in that chat, else into its turn queued there that hasn't started, else one turn of its own on no task, answering the sender's turn (a pause holds it as any turn Gathr queues). Refused with a reference: the sender itself, a name not in the chat, a chat of one agent, an archived chat. Each message is a hand-off record (`handoffs`): its depth is the sender's chain plus one, starting over after the person's message in the chat or a task there settling; past the limit (`handoff_limit` in `GET`/`PATCH /api/settings`, 50 by default, 1 to 1000, `null` for none) the message still shows, nobody is woken, and the chat is paused ("Paused after 50 hand-offs between agents. Resume to carry on."). Events: `gathr.message.send` (`from`, `to`, `chars`, `depth`, `delivered`: `in_turn`, `joined`, `queued`, `held`, `paused`; never the text) and `gathr.handoff.limit`.
